<decisions_already_made>
**1. Literal strings, no path helper.** A repo-wide grep confirms no `storefrontPath`/`storePath`
helper exists. Eleven call sites do not justify inventing one, and the codebase's stated preference
is against premature abstraction. After this fix the correct form is a bare relative path, which is
*less* than a helper would produce — a helper would exist only to return its own argument. Do not
create one. The durable protection is the Task 2 contract test, not an abstraction.

**2. `trackingPath` is in scope.** It is the same defect on the same shopper journey, one line, and
leaving it means "fix storefront navigation" ships with the storefront still broken at the last
step. It is called out explicitly here rather than folded in silently. Changing it forces the
matching one-line update to `tests/isolation/checkout-paths.test.ts:269-271`, which is also in
scope. Nothing else in that test file changes.

**3. The category chip keeps its query string.** `page.tsx:130` becomes
`href={\`/?category=${category.slug}\`}` — the leading `/` is required. A bare `?category=...`
would be relative to the *current* path and would break the chip when the shopper filters from
anywhere other than the storefront root.

**4. The gate targets `/s/${`, not `/s/`.** The template-literal form is the exact broken pattern
and it cleanly excludes the four legitimate occurrences in `<do_not_touch>` (`PageProps` uses a
plain string literal; `revalidatePath` lives outside `src/app/s`). Do not widen it.
</decisions_already_made>

| storefront page -> shopper browser | Every emitted `href`/`redirect`/`router.push` becomes a URL the browser will request back across the first boundary. |
