## Phase Goal

ROADMAP goal (verbatim): *A merchant can list a product and a customer can complete a full purchase through to a merchant-confirmed order, with stock, order state, and payment-claim integrity guaranteed server-side.*

Derived user story (same derivation 03-01 and 03-02 committed):
**As a** Cameroonian merchant and their customer, **I want to** list products and complete a purchase through WhatsApp, Mobile Money claim, or cash on delivery, **so that** the sale is recorded, the stock is correct, and the payment status is auditable.

**This plan's slice:** a merchant can *navigate their business* — the dashboard stops being a single page and becomes a shell with four new destinations, one of which shouts when a payment claim is waiting. Without this, `/dashboard/products` is a URL nobody can reach.

<objective>
Adopt the `AppShell` silhouette using the shadcn official `sidebar` block, migrate the two existing dashboard pages into it, wire the ORD-03/D-13 pending-claims badge, and land the complete Phase-3 copy module up front so no later plan has to invent user-facing text.

Purpose: 03-UI-SPEC.md § A. Navigation Shell makes nav mandatory this phase and flags the two-page migration as an explicit task in the same wave as the first new dashboard route — doing it now costs two pages, doing it later costs ten. Landing all the copy in one pass means every later plan reads `strings.*` instead of appending to a file four other plans are also appending to.
Output: `src/components/app-sidebar.tsx`, a rewritten dashboard layout, `pendingClaimCount()`, eight new `strings` namespaces, and a nav-contract unit test.
</objective>
