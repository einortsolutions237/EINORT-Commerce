## Phase Goal

ROADMAP goal (verbatim): *A merchant can list a product and a customer can complete a full purchase through to a merchant-confirmed order, with stock, order state, and payment-claim integrity guaranteed server-side.*

Derived user story (same derivation 03-01 through 03-05 committed):
**As a** Cameroonian merchant and their customer, **I want to** list products and complete a purchase through WhatsApp, Mobile Money claim, or cash on delivery, **so that** the sale is recorded, the stock is correct, and the payment status is auditable.

**This plan's slice:** the merchant finally has a way in. They tap `Add product`, type a name and a price, take five photos with the phone in their hand, declare Size and Color, set the stock for each combination, and save — and what comes back out on the storefront looks like it cost money to make. This is the moment the product promise in PROJECT.md is either kept or not.

<objective>
Build the A2 product create/edit form: the four cards, the shared client form, the D-10 image gallery wired end to end through 03-05's presign and finalize pipeline, and the D-05 live variant matrix driven by the same pure expander the server uses.

Purpose: 03-06 built the complete write layer, so this plan is pure UI over an existing contract — no second server implementation, no divergent validation. The one rule that makes that true is that the matrix the merchant sees and the matrix the server writes come from the same function.
Output: `/dashboard/products/new`, `/dashboard/products/[id]`, `product-form.tsx`, `image-gallery-field.tsx`, `variant-matrix-field.tsx`, a loading skeleton and a form-contract test.
</objective>
