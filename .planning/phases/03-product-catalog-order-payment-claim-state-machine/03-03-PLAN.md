## Phase Goal

ROADMAP goal (verbatim): *A merchant can list a product and a customer can complete a full purchase through to a merchant-confirmed order, with stock, order state, and payment-claim integrity guaranteed server-side.*

Derived user story (same derivation 03-01 and 03-02 committed — the ROADMAP `**Goal:**` line is not in `As a / I want to / so that` form):
**As a** Cameroonian merchant and their customer, **I want to** list products and complete a purchase through WhatsApp, Mobile Money claim, or cash on delivery, **so that** the sale is recorded, the stock is correct, and the payment status is auditable.

**This plan's slice:** an order's *life* becomes real and provable — every legal move, every refusal, and an audit row for each, demonstrable by `npm run test:full` before a single page exists. Every later slice (checkout, claims, the merchant queue) calls `transitionOrder()` and cannot move an order any other way.

<objective>
Build the ORD-01 transition registry, the single `transitionOrder()` chokepoint that writes `Order.state` and the ORD-05 `OrderEvent` in one transaction, the actor identity that makes an audit row meaningful, and the four rate limiters the rest of the phase imports.

Purpose: `Order.state` is the authority for what a customer sees and what a merchant may do. If two code paths can write it, ORD-05's audit trail becomes advisory. One registry plus one writer makes drift a compile error and a grep-test failure rather than a review catch.
Output: `src/server/orders/{state-machine,errors,transition}.ts`, `MerchantContext.userId`, four exported limiters, and three tests that prove the rules.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server Action → `transitionOrder` | Callers include an anonymous-customer path (claim submission) and an authenticated merchant path; the function cannot tell them apart except by the `actor` argument it is given |
| Merchant session → `OrderEvent.actorUserId` | The recorded "who" must come from the signed session, never from a request body |
| Anonymous internet → rate-limited surfaces | Order placement, claim submission, tracking lookup and presign mint are all reachable without an account |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Repudiation | A state change with no record of who made it | mitigate | `transitionOrder` writes the `OrderEvent` in the same transaction as the `Order.update`; an illegal-transition isolation case proves a rollback leaves neither |
