# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note (read first)

Phase 1 is almost entirely backend/infrastructure. It has exactly **four** user-facing surfaces, and no more:

| # | Route | Audience | Purpose |
|---|-------|----------|---------|
| 1 | `/signup` (root domain) | Prospective merchant | The only real form in this phase — email/password + live slug check (D-01, D-02, ONB-01) |
| 2 | `/` (root domain) | Anyone | Minimal placeholder, **not** a marketing site (D-06) |
| 3 | `/store-not-found` | Anonymous visitor | Branded EINORT failure page for unknown **and** suspended hostnames (D-04, D-05) |
| 4 | `app/s/[slug]/page.tsx` | Anonymous visitor | Placeholder storefront — proves resolution works, no catalog, no branding (Phase 4 replaces it) |

This contract governs **EINORT platform chrome** only. It does **not** govern the merchant storefront template system — that is Phase 4 (`TMPL-01`, zinc-monochrome DTC flagship). The two share the zinc family deliberately so the platform reads as one product, but the flagship template will have its own contract.

**Out of scope for this phase's UI:** login page (Phase 2), onboarding (Phase 4), dashboard (Phase 6), any product/cart/checkout surface, any i18n framework, dark mode.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (CLI) — **not yet initialized; repo is empty** |
| Preset | `--template next --base base --css-variables`, `tailwind.baseColor: "zinc"`, `style: "base-nova"` |
| Component library | Base UI (shadcn `--base base`, the current CLI default). Fall back to `--base radix` only if a required primitive is missing. |
| Icon library | `lucide-react` (shadcn default, `iconLibrary: "lucide"`) |
| Font | **Plus Jakarta Sans** — single family, loaded via `next/font/google`, weights 400 + 600 only, `display: "swap"`, exposed as `--font-sans` |
| Styling | Tailwind v4 (`@import "tailwindcss"`), OKLCH CSS variables in `src/app/globals.css`, `@theme inline` token mapping |
| Dark mode | **Not implemented in Phase 1.** Do not author a `.dark` block beyond whatever `shadcn init` scaffolds; light is the only supported appearance. |

### Initialization (executor task, run before any UI work)

The repo is greenfield — there is no `package.json`, so `shadcn init` cannot run today. Sequence it as:

1. `npx create-next-app@16.3.1` (TS, App Router, Tailwind, ESLint, `src/`, alias `@/*`)
2. `npx shadcn@latest init --template next --base base --css-variables -y`
3. Verify `components.json` contains `"baseColor": "zinc"` and `"iconLibrary": "lucide"`; set them if the preset chose otherwise.
4. `npx shadcn@latest add button input label form card alert separator skeleton sonner`

Font rationale: Plus Jakarta Sans is the typeface of the locked zinc-monochrome DTC visual reference (`PROJECT.md` Key Decisions). Reusing it for platform chrome costs nothing and makes the signup surface and the eventual flagship storefront feel like one product. **Outfit from the same reference is deliberately not adopted** — a second family is unjustifiable for four pages.

### Copy language — confirm before build

Phase 1 copy below is written in **French (fr-CM)**. Rationale: Douala/Littoral is francophone, and `CLAUDE.md` already prescribes `Intl.NumberFormat('fr-CM', …)` as the project's formatting locale. Strings are hardcoded — **no i18n library in V1** (30-day solo constraint). An English reference column is provided so a flip is a find-and-replace, not a rewrite.

> ⚠️ This is the one design decision not pre-answered by an upstream artifact. If the merchant-facing UI should be English, say so now — it is ~40 strings, cheap to change here and expensive to change after Phase 4.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, inline status row gap |
| sm | 8px | Label → input gap, helper-text offset |
| md | 16px | Default gap between form fields, card inner padding on mobile |
| lg | 24px | Card inner padding (≥sm breakpoint), gap between form groups |
| xl | 32px | Page gutter, gap between page header and content |
| 2xl | 48px | Vertical rhythm between major blocks |
| 3xl | 64px | Top/bottom page padding on `/` and `/store-not-found` |

**Exceptions:**
- **44px minimum touch target** on every interactive element (button height, tap area of the "Aller sur einort.com" link). Non-negotiable: this market is mobile-first on low-end Android. 44px is not on the 4-scale-as-padding but is a *dimension* constraint, not a spacing token — implement via `min-h-11` (44px).
- Signup card max-width **`max-w-md` (448px)** — a fixed layout constant, not a spacing token.

No other exceptions. Any value outside this table is a contract violation.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.2 |
| Display | 36px | 600 | 1.1 |

**Exactly 4 sizes, exactly 2 weights (400, 600).** No 300, no 500, no 700. No italics.

Role assignment for this phase:

| Role | Where it appears |
|------|------------------|
| Display | `EINORT` wordmark on `/`; "Boutique introuvable" on `/store-not-found` |
| Heading | "Créer votre boutique" on `/signup`; "Boutique en préparation" on the placeholder storefront |
| Label | Form field labels; the inline slug-status text; the `.einort.com` suffix adornment |
| Body | Everything else, including helper text, error text, and the root-domain tagline |

Body text on `/signup` and `/store-not-found` is capped at **`max-w-prose`** for readability. Never render 16px body at 400 weight on a zinc-950 background at less than 4.5:1 — see Color.

## Color

Zinc monochrome, editorial. The 10% accent in this system is **ink, not a hue** — that is the locked visual direction, not an oversight.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` (`--background`, white) | Page surface on all four routes |
| Secondary (30%) | `oklch(0.967 0.001 286.375)` (`--muted`, zinc-100) | Signup card fill, input fill, footer band, the `.einort.com` suffix adornment; paired with `--border oklch(0.92 0.004 286.32)` (zinc-200) for all hairlines |
| Accent (10%) | `oklch(0.21 0.006 285.885)` (`--primary`, zinc-900) | See reserved-for list below |
| Destructive | `oklch(0.577 0.245 27.325)` | Slug **taken** / **reserved** / **invalid** status; form field errors; signup failure alert. Nothing else. |

**Additional semantic token (must be added to `globals.css`, shadcn does not ship it):**

| Role | Value | Usage |
|------|-------|-------|
| Success | `--success: oklch(0.596 0.145 163.225)` (emerald-600) | Slug **available** status only. Not used for any button, badge, or border. |

Justification for a fifth color: D-02 requires a distinguishable available / taken / reserved tri-state. Signalling "available" with the absence of red is not a state — it is ambiguity. One green token, one usage.

**Supporting neutrals (from the zinc scale, not new colors):**
`--foreground: oklch(0.141 0.005 285.823)` (zinc-950, body text) · `--muted-foreground: oklch(0.552 0.016 285.938)` (zinc-500, helper text) · `--ring: oklch(0.705 0.015 286.067)`

**Accent reserved for:**
1. The primary CTA button fill (`Créer ma boutique` on `/signup`; `Créer ma boutique` on `/`) — **one primary button per page, never two**
2. The `EINORT` wordmark
3. Body/heading text color (as `--foreground`, zinc-950)
4. Focus ring on keyboard focus

**Accent is NOT for:** links (use `--foreground` + underline), input borders, card borders, icons, hover fills on secondary elements, or "all interactive elements."

**Contrast floors (WCAG AA, non-negotiable):** body text 4.5:1, Display/Heading 3:1, focus ring 3:1 against adjacent surface. `--muted-foreground` on `--muted` is the one pairing that must be spot-checked — if it fails, darken the helper text to `--foreground`, do not lighten the surface.

**Color is never the only signal.** Every slug status carries a lucide icon and a text label in addition to its color (WCAG 1.4.1).

**Voice:** direct, second person, no exclamation marks, no "Oops"/"Whoops", no emoji. Errors state what happened and what to do next.

A reviewer must be able to confirm the suspended and unknown paths render the **same component with the same props**.

**Do not write:** a login link on `/` (Phase 2), an onboarding CTA on `/s/[slug]` (Phase 4), a "contact support" link (no support surface exists), or any copy naming a phase, a plan tier, or an internal route (`/s/`, `scopedDb`, `proxy.ts`).

## Interaction & State Contract

### Slug availability check (D-02)

| Rule | Value |
|------|-------|
| Trigger | Debounced 400ms after last keystroke, **and** on blur |
| Minimum length before firing | 3 characters |
| Normalization | Lowercase + trim applied to the displayed value as the user types; the user never sees a value the server will reject on case alone |
| Stale response handling | Only the latest in-flight request may update state — discard earlier responses (request sequence number or `AbortController`) |
| Submit gating | Primary CTA is **disabled** while state is `checking`, `taken`, `reserved`, or `invalid`. It is **enabled** in the `check unavailable` state — the server is the authority (Pattern 2, layer 2), the client is UX only. |
| Announcement | Status region is `aria-live="polite"` with `role="status"`; the input carries `aria-describedby` pointing at it |
| Never | Never block typing, never auto-correct to a different slug, never suggest an alternative slug (out of scope) |

### Every surface must declare these four states

| State | Requirement |
|-------|-------------|
| Loading | Signup submit → button shows `Création en cours…`, is disabled, retains its width (no layout shift). No full-page spinner. |
| Empty | Only the placeholder storefront has one — see copy table. |
| Error | Rendered as a shadcn `alert` with `variant="destructive"` above the form, **and** the offending field marked `aria-invalid`. Never a toast alone for a blocking error. |
| Success | Signup success is a **redirect**, not a message. No success toast on a navigation. |

### Layout & responsive

| Rule | Value |
|------|-------|
| Breakpoint strategy | Mobile-first. Design at 360px width first — this market is low-end Android. |
| Signup layout | Single column, `max-w-md`, centered, card on `--muted` fill with `--border` hairline. Never two columns. |
| `/` and `/store-not-found` | Single centered column, vertically centered, `max-w-prose` body |
| Form field order | Email → Password → Store address → CTA. Store address is last so the slug check has the user's full attention. |
| No | No modals, no drawers, no carousels, no animation beyond the `loader-circle` spin and default focus/hover transitions in this phase. |

### Accessibility floor

- Every input has a visible `<label>` — placeholder-as-label is a contract violation.
- Visible focus ring on all interactive elements (`--ring`, ≥2px, 3:1 contrast).
- Full keyboard path through signup: tab order matches visual order, Enter submits.
- `<html lang="fr">` on all four routes (matches the copy language decision above).
- `/store-not-found` and `/s/[slug]` must render meaningful `<title>` text — a visitor arriving at a dead subdomain sees `Boutique introuvable · EINORT`, not `404`.
