<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Merchant-authored accent -> CSS custom property | The utility vocabulary decides what a merchant's colour is allowed to reach |
| Storefront design system -> dashboard design system | Two palettes on one deployment; a leak in either direction is the retrofit this project already paid for once |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02 | Tampering | The `brand-accent` utility vocabulary crossing into `(dashboard)` or `src/components` | mitigate | New ban #5 in `tests/unit/surface-token-isolation.test.ts`, mirroring ban #4's implementation and carrying both non-vacuity guards so it cannot pass over an empty scan. D-12 forbids weakening ban #4 for the editor; this plan strengthens the pair rather than touching it. |
| T-04-09 | Tampering / XSS-adjacent | The token vocabulary a merchant colour can reach | mitigate | The `@theme inline` mappings expose the accent ONLY as fill, text-on-fill, ring and secondary fill — there is deliberately no utility that lets a merchant colour a page background or body text (D-09). The value itself is regex-validated by `hexColorSchema` (plan 04-02) on write and on read; this plan bounds the blast radius even if that validation were bypassed. |
| T-04-03 | Information disclosure (accessibility) | Focus ring and reduced-motion floor | mitigate | `--brand-accent-ring` falls back to `var(--ring)` inside the storefront scope, so a tenant with no theme row still has a visible focus ring on a route tree containing checkout (WCAG 1.4.11/2.4.11). The `prefers-reduced-motion` block ships in the same commit as the motion tokens, so no window exists where animation is live and the floor is not. |
| T-04-17 | Tampering | Inline user-facing literals bypassing the copy contract | mitigate | All 60-odd strings land in `src/lib/strings.ts` in wave 1, before any consuming component exists, so no later plan has a reason to inline one. The existing prose-scan contract tests fail the build on an inline literal in a `.tsx`. |
| T-04-SC | Tampering | npm installs | accept | This plan installs nothing. 04-RESEARCH.md § Package Legitimacy Audit records a deliberate zero-install posture for the whole phase; the audit table is present and empty by design. |
</threat_model>
