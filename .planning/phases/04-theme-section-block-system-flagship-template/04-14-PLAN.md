<objective>
Build the iframe target: a public, unindexed `/preview` route on the tenant subdomain that renders the published storefront on first paint and then re-renders from a `postMessage` draft with no network in the loop.

Purpose: D-07 asks for a preview that updates as the merchant types. Three independently verified constraints force this shape — `src/proxy.ts` hard-404s any `/s/*` request so the editor cannot iframe the internal route; ban #4 forbids `data-surface="storefront"` outside `src/app/s/` and D-12 forbids weakening it, so the preview cannot be an inline dashboard subtree; and an inline preview would get the window's viewport, firing every `md:` breakpoint against the browser width rather than the pane width at exactly the moment the merchant is judging quality. The iframe solves all three and makes a device-size toggle a width change.

Output: `preview/page.tsx` and `preview-canvas.tsx`.
</objective>

Create `src/app/s/[slug]/preview/preview-canvas.tsx`, `"use client"`.

Props: `{ initialDocument: PageDocument; initialTokens: ThemeTokens; data: StorefrontRenderData;
editorOrigin: string }`. Two `useState`s seeded from the initial props, so the first paint is the
PUBLISHED storefront and the pane is never blank.

The message handler, in EXACTLY this order — each step is a separate mitigation and reordering
them defeats the earlier ones:

1. `if (event.origin !== editorOrigin) return;` — **the first line, before `event.data` is touched
   at all.** A `postMessage` handler that skips this accepts a document from any page that frames
   it. Comment it as such.
2. Shape-check the envelope: it must be a non-null object with a `type` of
   `"einort:preview-doc"` or `"einort:preview-select"`. Anything else returns.
3. `pageDocumentSchema.safeParse(envelope.document)` and `themeTokensSchema.safeParse(envelope.tokens)`.
   **Never `JSON.parse` and trust.** Apply each result only if it succeeded; a failed parse is
   ignored SILENTLY — fail closed on a render path rather than throwing, the same posture
   `resolve.ts` takes for an unknown `planTier`.
4. Only then `setState`.

Handshake: on mount, `window.parent.postMessage({ type: "einort:preview-ready" }, editorOrigin)` —
an **exact** `targetOrigin`, never `"*"`. The editor holds its first document post until this
arrives, so no message is lost to a race with hydration. Add the listener BEFORE posting ready.
Return the remover from the effect, following `use-mobile.ts`'s idiom.

`einort:preview-select`: scroll the named section into view (`behavior: "smooth"`, or `"auto"`
when `prefers-reduced-motion: reduce` matches) and draw
`outline-2 outline-offset-[-2px] outline-ring` on it for 2 seconds, then fade. Zinc-400 is
visible on both the white sections and the ink editorial band, which is why the ring rather than a
fill.

Render: a wrapper `div` whose `style` carries the five values from `deriveThemeCssVars(tokens)`,
then `document.sections.map((section) => <SectionRenderer key={section.id} section={section} data={data} />)`.
The wrapper's token values OVERRIDE the layout's for the duration of the draft — that is how a
colour change appears instantly with no server round trip. Every value is a variable, so ban #1
passes. Re-validate both accents with `hexColorSchema` before they reach the `style` object even
though step 3 already parsed them — that parse validated the ENVELOPE; this one guards the
render, and Pitfall 3 asks for validation on write AND on read.

**Navigation is intercepted.** Inside `/preview`, anchor activation (click AND `Enter` keydown) is
prevented and does nothing; anchors render `cursor-default`. The merchant cannot navigate the
preview away from the home document this phase. This preserves full visual fidelity of the header
and footer links without producing a dead end. Implement it at the wrapper with a delegated
handler rather than by rewriting every section's anchors.

**Clicking a section does NOT select it this phase.** The rail is the only selection surface.
State that in the header so it is not read as half-built.

Why this is genuinely instant, worth recording in the header: `postMessage` between two documents
in the same browser is a structured-clone hop measured in microseconds and React re-renders a
five-section tree in a frame. There is no network in the loop at all — a stronger guarantee than
Shopify's own theme editor, which re-renders a section server-side on a settings change. On a
Douala mobile connection a per-keystroke round trip is not "instant" under any definition.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser `postMessage` -> preview document | Untrusted structured-clone payload from any page that can frame this route |
| Public `/preview` URL | Unauthenticated, shareable, crawlable by default |
| Draft JSONB values -> CSS custom properties | A colour string reaches `style.setProperty` inside the iframe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-08 | Spoofing / Tampering | A hostile page framing `/preview` and posting a document | mitigate | `if (event.origin !== editorOrigin) return;` is the FIRST statement of the handler, before `event.data` is touched — asserted by a code-order acceptance criterion. `editorOrigin` is computed server-side from `NEXT_PUBLIC_ROOT_DOMAIN`, never from `window.location`. The payload is then shape-checked and `safeParse`d, and a failure is ignored silently rather than thrown on a render path. |
| T-04-08b | Information disclosure | The editor broadcasting the merchant's draft to an arbitrary origin | mitigate | The iframe's `einort:preview-ready` post uses an EXACT `targetOrigin`, never `"*"` — asserted by a grep acceptance criterion. Plan 04-15's sender does the same. A wildcard here would hand the merchant's unpublished draft to whatever page happened to be loaded. |
| T-04-09 | Tampering / XSS-adjacent | A draft accent reaching `style.setProperty` inside the iframe | mitigate | `hexColorSchema` is applied a SECOND time, immediately before the `style` object, on top of the envelope's `themeTokensSchema.safeParse`.
