<objective>
Wire the published document and the merchant's brand tokens into the live storefront — the moment TMPL-01 and EDIT-01 become visible to a real customer.

Purpose: everything before this plan is a schema, a registry, a set of components and a set of actions. This is where a shopper on `{slug}.einort.com` gets the flagship. It is also where D-09's guardrail becomes structural: the accent enters the page as five CSS custom properties whose foreground and focus-ring values are DERIVED server-side, so a merchant can tint their storefront and can never produce an unreadable button label or an invisible focus ring on a route tree that contains checkout.

Output: token injection and chrome in `layout.tsx`, a translucent logo-aware `store-header.tsx`, a new three-row `store-footer.tsx`, and a `page.tsx` that renders sections instead of a hardcoded grid.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JSONB column -> CSS custom property | A merchant-authored (or bad-backfill) colour string reaches `style.setProperty` |
| Public storefront render -> database | Anonymous, unauthenticated, unlimited traffic |
| Merchant payment settings -> outbound `wa.me` link | A stored phone number becomes a live external link |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering / XSS-adjacent | `tokens.primaryAccent` / `secondaryAccent` reaching the layout's `style` object | mitigate | `hexColorSchema.safeParse` is applied ON READ in `layout.tsx`, not only on write, and fails CLOSED to `DEFAULT_PRIMARY_ACCENT` rather than throwing on a render path. React sets custom properties via `setProperty` without sanitising, so `red; background-image: url(https://evil/x)` from a bad backfill is stopped by this regex and by nothing else (ASVS V5, Pitfall 3). |
| T-04-03 | Information disclosure (accessibility) | An unreadable button label or an invisible focus ring at an arbitrary merchant accent | mitigate | `--brand-accent-foreground` and `--brand-accent-secondary-foreground` are DERIVED by `accentForeground()` server-side, and `--brand-accent-ring` falls back to zinc-400 below 3:1 against white. WCAG 1.4.3 / 1.4.11 / 2.4.11 on a route tree containing checkout is not merchant-discretionary; D-11's non-blocking warning is reserved for the accent-as-link taste judgement. |
| T-04-02 | Tampering | `data-surface="storefront"` and the brand tokens escaping this subtree | mitigate | The attribute stays on the single existing div in `layout.tsx`; the token `style` object is attached to that same div. | T-04-11 | Denial of service | Write amplification on the public render path | mitigate | `getPublishedStorefront` performs no write (plan 04-09, asserted there), and this plan adds none — no lazy seed, no cache write, no Redis widening.
