<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tenant A caller -> tenant B rows | The boundary `scopedDb` exists to make structural rather than conventional |
| Direct action invocation -> entitlement gate | An attacker never loads the page whose disabled button is the "control" |
| Untrusted payload -> write target | An extra field in a request body must not be able to name a different tenant |

Tenant B's row is read back and compared against the seeded fixture after every tenant-A write. |
