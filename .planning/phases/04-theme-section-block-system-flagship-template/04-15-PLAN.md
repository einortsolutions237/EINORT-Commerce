Create `editor-shell.tsx`, `"use client"`. It is WIRING. Resist adding logic.

**State:** one `useReducer(editorReducer, initialState)` from `@/lib/editor/reducer`. Every
reorder and every field edit is an `EditorAction` dispatch. Do NOT write a second reducer, a
`patch()` updater, or an inline `setState` that mutates the document — the reducer is the only
place EDIT-02's logic has automated coverage in a repo with no jsdom, and duplicating a transition
here silently removes that coverage.

**The postMessage sender:**
- hold an `iframeRef` and a `readyRef` (or a `ready` state)
- listen for `einort:preview-ready` from the preview's exact origin, applying the same
  origin-first discipline the receiver uses: check `event.origin` BEFORE reading `event.data`
- until ready, queue nothing and send nothing — the handshake exists so no document post races
  hydration. Post the first `einort:preview-doc` on receiving ready.
- after every reducer action, post `{ type: "einort:preview-doc", document, tokens }` with an
  **exact** `targetOrigin` (the preview origin), never `"*"`. There is no network in this loop, so
  there is no reason to debounce and D-07 forbids one.
- on `select`, additionally post `{ type: "einort:preview-select", sectionId }`

**The iframe:** `src={previewUrl}` (passed in from the RSC — do NOT build it here from
`window.location`; Pitfall 12), `title` from `strings.editor`, `className="h-full w-full"`.

**Loading state:** before the handshake, the iframe is `opacity-0` and an overlay renders a
`skeleton` silhouette MATCHING THE FLAGSHIP'S SHAPE — one tall block (hero), one short band (trust
bar), a 2x2 tile grid — plus a `role="status" aria-live="polite"` line
`Loading your storefront preview…`. **No bare spinner.** On handshake, fade the iframe in over
200ms and remove the overlay.

**Handshake timeout:** no `einort:preview-ready` within 10s replaces the overlay with a
**non-destructive** `alert` carrying `strings.editor`'s
*The preview didn't load. Your changes are safe — try loading it again.* plus an outline
`Reload preview` button (`rotate-ccw`) that resets the iframe `src`. Non-destructive is the point:
the draft is intact and the copy says so.

**Layout:**
- `>=lg`: two panes at full editor width (**not** `max-w-5xl` — the editor needs the viewport).
  Left a fixed 320px (`w-80`) rail, `bg-card border-r border-border`, its own scroll. Right the

- `<lg`: no side-by-side at 360px. A `toggle-group` at the top switches `Edit` / `Preview`, each
  full-width. Default `Edit`.
- **Viewport toggle:** a `toggle-group` top-right of the preview pane, above the frame.
  `monitor` = Desktop (iframe `w-full`); `smartphone` = Mobile (iframe
  `w-[390px] max-w-full mx-auto h-[844px] max-h-full`). Visible text labels at `>=md`, icon-only

**The rail is push/pop:** the list by default; selecting an entry replaces the rail content with

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Editor document (apex) -> preview document (subdomain) | Two origins exchanging the merchant's unpublished draft |
| Rendered editor UI -> capability | The disabled Save/Publish buttons are not an authorization decision |
| `(dashboard)` layout -> page authorization | A Next 16 layout cannot be the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-04-08 | Spoofing / Tampering | The `postMessage` sender | mitigate | Every send uses an EXACT `targetOrigin` computed server-side from `NEXT_PUBLIC_ROOT_DOMAIN` and passed in as `previewOrigin` — never `"*"`, never derived from `window.location`. The `einort:preview-ready` listener checks `event.origin` before reading `event.data`, mirroring the receiver's discipline in plan 04-14. A wildcard here would broadcast the merchant's unpublished draft to whatever origin happened to be loaded. |
