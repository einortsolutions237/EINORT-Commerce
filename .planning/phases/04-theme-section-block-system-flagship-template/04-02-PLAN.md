<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser `postMessage` → preview document | Untrusted structured-clone payload from any framing page |
| JSONB column → CSS custom property | A merchant-authored (or bad-backfill) colour string reaches `style.setProperty` |
| Server Action body → `StorefrontPage.draft` | Untrusted request body from a direct POST |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering | `hexColorSchema` → `--brand-accent` custom property | mitigate | `/^#[0-9a-fA-F]{6}$/` is enforced on write AND on read-back. React sets custom properties via `setProperty` and does not sanitise, so a value like `red; background-image: url(https://evil/x)` is only stopped by this regex (ASVS V5). The read path fails closed to `DEFAULT_PRIMARY_ACCENT` rather than throwing on a render path. |
| T-04-08 | Spoofing / Tampering | `pageDocumentSchema` as the `postMessage` payload validator | mitigate | The schema carries no `tenantId`, no price and no product id, so a forged payload can only change presentation inside the receiving document. Plan 04-14 pairs it with an exact `event.origin` check before `event.data` is read. |
| T-04-04 | Elevation of privilege | Any theming schema carrying a tenant field | mitigate | No schema in this file declares `tenantId`. `merchantAction` resolves identity from the session before the handler runs and `scopedDb` stamps the tenant last, so there is no field a direct POST could set to retarget a write. Asserted by `grep -c "tenantId" src/server/theming/schema.ts` returning 0. |
| T-04-12 | Denial of service | An incompatible settings rename orphaning live published documents | mitigate | `version: z.literal(1)` makes a rename a refused parse rather than a silent misread; plan 04-10's read path `safeParse`s and degrades to registry defaults with a `console.error`, so a bad deploy shows default copy instead of a white screen. |
| T-04-03 | Information disclosure (accessibility) | Merchant accent chosen with unreadable foreground | mitigate | `accentForeground()` derives the button label colour server-side rather than warning about it, and `deriveThemeCssVars` falls the focus ring back to zinc-400 below 3:1 — WCAG 1.4.11/2.4.11 on a route tree containing checkout is not merchant-discretionary. |
| T-04-SC | Tampering | npm installs | accept | Zero packages installed. The WCAG maths is hand-rolled deliberately (04-RESEARCH.md § Don't Hand-Roll) rather than pulling `wcag-contrast`/`colord`. |
</threat_model>
