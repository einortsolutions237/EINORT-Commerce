Build the code side of EDIT-01's Theme→Page→Section→Block model: the section-type registry, the six-segment industry list, the flagship template entry, the default document — and the drift test that keeps all of it aligned with the Zod union from plan 04-02.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `Organization.industry` (a nullable String column) -> application logic | A bad backfill or a future direct write can put any string there |
| Registry vs. schema | Two lists of the same field names in two files; drift is invisible at runtime until a merchant edits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-21 | Tampering | An unknown value in `Organization.industry` | mitigate | `isIndustrySegment` narrows `unknown` to the closed six-member set, copied verbatim from `isPlanTier`'s body. Callers narrow before use; nothing in this phase renders a template FROM the industry (D-01), so an unknown value degrades to "no segment selected" rather than to an unrenderable storefront. |
| T-04-12 | Denial of service | A settings key renamed on one side only, orphaning live published documents | mitigate | `tests/unit/theming-registry.test.ts` fails the build when a descriptor key has no schema key or a schema key has no descriptor. Paired with `version: z.literal(1)` (plan 04-02) and the `safeParse`-with-defaults read path (plan 04-09), a rename becomes a red test at commit time rather than a white screen in production. |
| T-04-04 | Elevation of privilege | A tenant field entering the registry or the defaults | mitigate | Neither file declares, accepts or emits a `tenantId`. `flagshipDefaultDocument()` takes no parameters at all; the tenant is resolved from the session by `merchantAction` before any consumer runs, and `scopedDb` stamps it last. |
| T-04-22 | Tampering | A shared mutable default document | mitigate | `flagshipDefaultDocument()` and `flagshipDefaultTokens()` are functions returning fresh objects, asserted by a mutation test. A frozen module-level literal would be corrupted for every subsequent tenant seed and every storefront read-path fallback by one careless caller. |
| T-04-17 | Tampering | User-facing prose leaking into a registry | mitigate | Every `label` / `helper` / default settings value is a `strings.*` member expression; asserted by a grep acceptance criterion on both files. `plans.ts`'s header documents the same split for plan copy. |
| T-04-SC | Tampering | npm installs | accept | This plan installs nothing. Zod 4.4.3 is already installed; 04-RESEARCH.md § Package Legitimacy Audit records the phase's zero-install posture. |
</threat_model>
