## Phase Goal

**As a** merchant, **I want to** sign in to a dashboard that knows which store is mine from my session alone and shows my plan and trial state, **so that** I can run my store knowing my subscription limits are enforced on the server, not just displayed in the UI.

<objective>
Build the merchant Data Access Layer and the write gate, then put a real dashboard on top of them: the shell, the trial banner, the store summary page and the suspended page.

Purpose: TEN-04 is satisfied structurally by one parameterless, session-derived resolver; SUB-02's read-only mode (D-08) needs a wrapper that makes the guarded action the easiest action to write; D-11/D-12 need a countdown computed on the server.
Output: `requireMerchantContext()`, `merchantAction()`, `/dashboard` with a persistent trial banner, and `/suspended`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → dashboard route segments | Any authenticated user can request any dashboard path directly, bypassing client navigation |
| browser → Server Actions built with `merchantAction` | Reachable by direct POST; treat as public API endpoints |
| proxy → app | `src/proxy.ts` performs no I/O and validates nothing; it is a routing layer, not a gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Elevation of Privilege | Tenant identity in the dashboard | mitigate | `requireMerchantContext()` takes no parameters and reads `session.session.activeOrganizationId` only; `tests/unit/no-tenant-id-param.test.ts` fails the build if any exported merchant function grows a tenant-id parameter |
| T-02-12 | Elevation of Privilege | Auth check placed in `(dashboard)/layout.tsx` | mitigate | Every page calls the DAL itself; the layout uses it for banner data only and `grep -c "redirect(" layout.tsx` is asserted 0 |
| T-02-13 | Elevation of Privilege | Write attempted after trial expiry | mitigate | `merchantAction({ mode: "write" })` refuses on `!ctx.canWrite` before parsing or touching the database; disabled UI controls are explicitly assumed bypassed |
| T-02-14 | Tampering | Trial countdown derived from the client clock | mitigate | `daysLeft` is a server-computed integer prop; no `Date` object and no date string reaches the banner component |
| T-02-15 | Information Disclosure | Suspension state exposed to anonymous visitors | mitigate | `/suspended` is reachable only behind a session whose active organization is the suspended one; `/store-not-found` keeps byte-identical output for unknown, unclaimed and suspended hostnames |
| T-02-16 | Information Disclosure | Whole organization row serialized to a client component | mitigate | The DAL `select`s eight explicit columns as a DTO and returns `MerchantContext`, never a Prisma row |
| T-02-17 | Spoofing | Session outlived its organization (deleted or mid-migration) | mitigate | A missing organization row redirects to `/login` — fail closed, no default tenant branch |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | Zero packages installed in this plan; any deviation requires a blocking human checkpoint |
</threat_model>
