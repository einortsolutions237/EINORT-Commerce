# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note (read first)

Phase 2 is a **mechanism phase** (02-RESEARCH.md § Summary), but unlike Phase 1 it ships real merchant-facing product surface. This contract governs exactly **six** surfaces and no more:

| # | Route | Audience | Purpose | Source |
|---|-------|----------|---------|--------|
| 1 | `/login` (apex) | Returning merchant | Dashboard sign-in. 01-07-SUMMARY deliberately left `/signup` with no sign-in link; building it is this phase's job. | TEN-04 |
| 2 | `/onboarding/plan` (apex, authenticated) | New merchant, mid-signup | Mandatory plan pick between signup submit and the storefront redirect | D-01 – D-05 |
| 3 | `(dashboard)` shell + `/dashboard` (apex) | Signed-in merchant | Dashboard chrome, trial banner, read-only banner, store summary | TEN-04, D-08, D-11, D-12 |
| 4 | `/dashboard/plan` (apex) | Signed-in merchant, **active trial only** | Plan switch | D-06, OQ-3 |
| 5 | `/suspended` (apex, authenticated) | Merchant whose org is `status !== "active"` | Terminal state for a suspended organization | OQ-5 |
| 6 | `/signup` (amendment only) | Prospective merchant | Add the one missing sign-in link. No other change to the Phase 1 form. | D-01 |

**Out of scope for this phase's UI:** the subscribe-via-claim form (D-10 — Phase 3+), any product/order/catalog surface (Phase 3), the theme editor and storefront template (Phase 4), the platform Super Admin surface (Phase 6), annual-pricing toggle, invoices/billing history, email reminders (D-13), dark mode, i18n.

**Inheritance rule:** every token table below is **inherited verbatim from `01-UI-SPEC.md`** unless a row is explicitly marked `AMENDED` or `NEW`. Phase 2 introduces **zero** new spacing values, **zero** new type sizes, **zero** new weights, and **zero** new color tokens. Two amendments exist, both to `--destructive`'s reserved-for list, and both are justified in § Color.

## Spacing Scale

Inherited verbatim from `01-UI-SPEC.md`. Values must be multiples of 4.

| Token | Value | Usage in Phase 2 |
|-------|-------|------------------|
| xs | 4px | Icon-to-text gap in banners and feature bullets |
| sm | 8px | Label → input gap; gap between a feature bullet and the next |
| md | 16px | Default gap between form fields; card inner padding on mobile; banner inner padding |
| lg | 24px | Plan-card inner padding (≥sm breakpoint); gap between plan cards; gap between form groups |
| xl | 32px | Page gutter; gap between page header and content |
| 2xl | 48px | Vertical rhythm between major dashboard blocks |
| 3xl | 64px | Top/bottom page padding on `/login`, `/onboarding/plan`, `/suspended` |

**Exceptions (all inherited, none new):**
- **44px minimum touch target** on every interactive element — buttons, the whole plan-selection card (it is the radio's label, so the entire card is the tap target), the WhatsApp contact link, the sign-out control. Implement via `min-h-11`. Non-negotiable: mobile-first, low-end Android market.

Any value outside this table is a contract violation.

## Typography

Inherited verbatim. **Exactly 4 sizes, exactly 2 weights (400, 600).** No 300, no 500, no 700, no italics.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.2 |
| Display | 36px | 600 | 1.1 |

Role assignment for this phase:

| Role | Where it appears |
|------|------------------|
| Display | **Unused in Phase 2.** Reserved for the `EINORT` wordmark and `/store-not-found` (Phase 1). Do not reach for it for a plan price. |
| Heading | Page headings: `Sign in`, `Choose your plan`, `Your store`, `Your plan`, `Your store is unavailable`. Plan tier price. Plan tier name. |
| Label | Form field labels; the `Most Popular` badge; the plan-card tier tagline; the trial-banner text; `Everything in Starter, plus` group headers |
| Body | Everything else — sublines, feature bullets, error text, read-only explanation, helper text |

**Type-role collision to resolve deliberately:** the plan **price** and the plan **tier name** both use Heading (24px/600). Differentiate by color, not by size or weight — tier name is `--foreground`, price is `--foreground` with the `/month` suffix in Body + `--muted-foreground`. Inventing an 18px or a 500-weight to separate them is a contract violation.

Body text is capped at **`max-w-prose`** wherever it runs as a paragraph (login subline, read-only explanation, suspended body).

## Color

Zinc monochrome, editorial. The 10% accent is **ink, not a hue** — the locked visual direction. Values are already live in `src/app/globals.css`; this table is the contract they satisfy, not a change request.

| Role | Value | Usage in Phase 2 |
|------|-------|------------------|
| Dominant (60%) | `oklch(1 0 0)` (`--background`, white) | Page surface on all six routes; dashboard content area |
| Secondary (30%) | `oklch(0.967 0.001 286.375)` (`--muted`, zinc-100) | Login card fill; non-recommended plan-card fill; neutral trial-banner fill; dashboard header band. Paired with `--border oklch(0.92 0.004 286.32)` (zinc-200) for every hairline. |
| Accent (10%) | `oklch(0.21 0.006 285.885)` (`--primary`, zinc-900) | See reserved-for list |
| Destructive | `oklch(0.577 0.245 27.325)` | **AMENDED** — see below |
| Success | `oklch(0.596 0.145 163.225)` (`--success`, emerald-600) | **Slug availability only (Phase 1). Not used anywhere in Phase 2.** Do not reach for it to mark the selected plan card or a successful plan switch. |

**Supporting neutrals (zinc scale, not new colors):** `--foreground: oklch(0.141 0.005 285.823)` (zinc-950) · `--muted-foreground: oklch(0.552 0.016 285.938)` (zinc-500) · `--ring: oklch(0.705 0.015 286.067)`

### Accent (`--primary`) reserved for

1. The single primary CTA button fill on each surface — `Sign in`, `Start my 10-day trial`, `Switch to {plan}`. **One primary button per page, never two.**
2. The `Most Popular` badge fill on the Business plan card (`badge variant="default"`).
3. The 2px selection ring on the currently selected plan card, and the `check` icon inside it.
4. Body/heading text color (as `--foreground`, zinc-950).
5. Focus ring on keyboard focus.

**Accent is NOT for:** links (use `--foreground` + underline), input borders, card borders, feature-bullet `check` icons (those are `--muted-foreground`), the trial banner in its neutral state, hover fills, or "all interactive elements."

### Destructive — two amendments to Phase 1's reserved-for list

`01-UI-SPEC.md` scoped `--destructive` to "slug status / form field errors / signup failure alert. Nothing else." Phase 2 extends it to exactly two more usages:

| AMENDED usage | Why |
|---------------|-----|
| The **urgent** trial banner (`daysLeft <= 2`) — icon, text, hairline, and a `--destructive/10` tint fill | D-12 requires an escalation to "warning/red". The alternative is a sixth token (amber). Rejected: Phase 1 justified `--success` because a tri-state needs a positive signal that red's absence cannot carry; here the escalation is a **two-state** neutral→urgent, and neutral is exactly "no red". A warning color would buy nothing and would double the palette's hue count for a single banner. |
| The **read-only / trial-expired** banner and the inline write-refusal error | This is a genuine blocked state with an error result behind it (`merchantAction` returns `{ ok: false }`), which is precisely what the existing destructive form-error usage already covers. |

`--destructive` remains forbidden for: any plan-tier styling, the Starter tier, downgrade affordances, the suspended page's fill, and any decorative use.

### Non-negotiable color rules

- **Contrast floors (WCAG AA):** body text 4.5:1, Heading 3:1, focus ring 3:1 against the adjacent surface. `--muted-foreground` on `--muted` is the pairing to spot-check; if it fails, darken the text to `--foreground` — never lighten the surface.
- **Color is never the only signal.** The urgent trial banner carries a `triangle-alert` icon **and** copy that names the state; the neutral banner carries `clock`. The selected plan card carries a `check` icon **and** `aria-checked`, not just a ring. Read-only controls are `disabled` **and** explained in copy (WCAG 1.4.1).
- **Never signal read-only mode by color alone**, and never by hiding a control. See § Interaction.

## Formatting

| Value | Rule |
|-------|------|
| Plan prices | `new Intl.NumberFormat("fr-CM", { style: "currency", currency: "XAF", maximumFractionDigits: 0 }).format(5000)`. **Never hardcode `"5,000 FCFA"` or `"5 000 FCFA"` in a string.** XAF has no decimal subunit in common use — `maximumFractionDigits: 0` is required, not cosmetic. Copy language is English; number/currency formatting is `fr-CM` per CLAUDE.md. The two are independent and both are deliberate. |
| Billing period suffix | The literal `/month` lives in `strings.ts` and is concatenated as a separate Body-role element beside the formatted price — it is never baked into the `Intl` output. |
| Days remaining | Rendered from the **server-computed integer** `ctx.trial.daysLeft`. The client never receives a date to subtract from its own clock (02-RESEARCH.md Pitfall 8). |
| Annual prices | **Not rendered.** The annual figures in `pricing-reference.md` are real but the annual toggle is explicitly deferred. Show monthly only; do not add a "billed annually" line. |

### Dashboard — trial banner (D-11, D-12)

| State | Condition | Icon | Copy |
|-------|-----------|------|------|
| Neutral | `trial.state === "active"` and `daysLeft >= 3` | `clock` | `{days} days left in your trial.` · action link `Change plan` → `/dashboard/plan` |
| Urgent | `trial.state === "active"` and `daysLeft <= 2` | `triangle-alert` | `{days} days left in your trial.` · action link `Change plan` → `/dashboard/plan` |
| Urgent, singular | `daysLeft === 1` | `triangle-alert` | `1 day left in your trial.` · action link `Change plan` |
| Expired / read-only | `trial.state === "expired"` | `triangle-alert` | Heading: `Your trial has ended.` Body: `You can still see your store and your data, but you can't make changes until you subscribe.` CTA: `Contact us to subscribe` |
| Subscribed | `trial.state === "subscribed"` | — | **No banner.** Render nothing. |

**Threshold, locked (Claude's discretion per CONTEXT.md):** urgent begins at `daysLeft <= 2`. This is the upper bound of D-12's "final 1-2 days" and matches 02-RESEARCH.md Code Example 8 (`urgent={ctx.trial.daysLeft <= 2}`) so the spec and the reference implementation cannot drift. It is a single constant, unit-tested at the day-3 / day-2 boundary.

**`daysLeft` is never 0 while `state === "active"`** — `resolveEntitlements` uses `Math.ceil`, so a trial with three hours left reports `1`. There is deliberately no "0 days left" copy and no hours/minutes countdown. Do not add one.

**Pluralization:** two separate strings (`trialDaysLeft` with a `{days}` token, `trialOneDayLeft` with none), selected by a `=== 1` check. No `Intl.PluralRules`, no `"day(s)"`.

## Interaction & State Contract

### Plan selection (`/onboarding/plan`)

| Rule | Value |
|------|-------|
| Semantics | A `<fieldset>` with a visually-hidden `<legend>` containing three **native `<input type="radio">`** elements, each visually hidden inside a `<label>` that *is* the card. **Do not install a `radio-group` component** — C-15 records that shadcn's `form` ships empty under the Base UI registry, and native radios give correct arrow-key roving focus, `aria-checked` and form semantics for free. |
| Tap target | The **entire card** is the label, therefore the entire card is the tap target. Comfortably clears the 44px floor. |
| Default selection | **None.** Business carries the `Most Popular` badge (D-04's "pre-highlighted") but is **not pre-checked**. Interpretation locked: D-05's "mandatory pick" is a deliberate act, and pre-checking would let a merchant be assigned a 12,500 XAF tier by inertia. |
| Submit gating | Primary CTA is **disabled** until a tier is checked, then enabled. Mirrors Phase 1's slug-check gating idiom. |
| Selected treatment | 2px `--primary` ring (unselected cards: 1px `--border` hairline), plus a `check` icon in `--primary` with a visually-hidden `Selected`. Fill does **not** change — no `--muted` → white swap, which would cause a visible reflow-free but jarring value shift on a monochrome palette. |
| Recommended treatment | `Most Popular` badge only. The Business card is **not** larger, not scaled, not elevated, and not pre-selected. |
| Order | Starter → Business → Professional (ascending price) at every breakpoint. Business is *not* re-ordered to the center on mobile — comparability by price beats visual centering. |
| Already-chosen case | If `planTier !== null`, the route redirects to the storefront rather than rendering (02-RESEARCH.md Pattern 7). No "you already picked" screen. |
| Navigation on success | `router.push` is **wrong** for the final hop — the storefront is a different origin, so it stays `window.location.assign(storeOrigin(slug))`. The signup → plan hop *is* same-origin and must use `router.push("/onboarding/plan")`. |
| Never | Never render a price the client computed; never show a card field; never offer a comparison table view; no carousel; no accordion on mobile — the cards stack and the page scrolls. |

### Read-only mode (D-08) — the state the merchant must never be confused about

| Rule | Value |
|------|-------|
| Disable, never hide | Every write control stays **rendered** and becomes `disabled` + `aria-disabled="true"` with `aria-describedby` pointing at the read-only banner. Hiding controls makes the dashboard look broken rather than restricted, which is exactly the confusion CONTEXT.md `<specifics>` forbids. |
| Reads keep working | The dashboard loads, data renders, navigation works. D-08 is read-only, not lockout. Never redirect an expired merchant away from `/dashboard`. |
| The banner is the explanation | One persistent read-only banner at the top of the dashboard shell, always visible while expired — not a tooltip the merchant must discover. |
| Server refusal surfaces in place | If a write is attempted anyway, `merchantAction` returns `{ ok: false }` and the message renders as a `role="alert"` **at the control the merchant used**, not as a toast and not as a page redirect. |
| Client gating is UX only | The disabled attribute is assumed bypassed. It is never the control — 02-RESEARCH.md § Architectural Responsibility Map. |

### Trial banner

| Rule | Value |
|------|-------|
| Placement | Top of the `(dashboard)` shell, above `{children}`, full content width |
| Live-region semantics | **Not** `aria-live`. It is persistent page furniture, not an update — announcing it on every navigation is noise. Render as a `<section>` with an accessible name. The **write-refusal** message is the thing that gets `role="alert"`. |
| Dismissible | **No.** D-11 says persistent. No close button, no `localStorage` dismissal. |
| Data source | The server-computed integer from the DAL, passed as a prop. Never `new Date()` in a client component. |
| Rendering the shell | The layout may *render* banner data from the DAL — that is a data use, not an auth check. It must **not** be the thing that authorizes (02-RESEARCH.md Pitfall 2). |

### Every surface must declare these four states

| State | Requirement |
|-------|-------------|
| Loading | Submit → button swaps to its `…` label, is disabled, and **retains its width** (no layout shift). No full-page spinner. `loader-circle` spin is the only permitted animation. |
| Empty | `/dashboard` in Phase 2 has no lists yet — it renders the § Copywriting empty state (`Your store is live`) with a `View my store` link and **no CTA to a route that does not exist yet**. Do not add "Add your first product" — Phase 3 owns that. |
| Error | shadcn `alert` with `variant="destructive"` above the form, **and** the offending field marked `aria-invalid`. Never a toast alone for a blocking error. |
| Success | Login success and plan-selection success are **redirects**, not messages — no success toast on a navigation. Plan-switch success stays on the page and renders an inline confirmation line. |

### Layout & responsive

| Rule | Value |
|------|-------|
| Breakpoint strategy | Mobile-first. Design at **360px** first. |
| `/login`, `/suspended` | Single column, `max-w-md`, centered, card on `--muted` fill with `--border` hairline, `rounded-lg` — identical construction to `/signup` (see `src/app/signup/page.tsx`, which overrides the shadcn `Card` defaults rather than re-authoring them). |
| `/onboarding/plan` | `max-w-5xl`. **1 column** below `lg`, **3 equal columns** at `lg` and up. Cards are equal-height in the row (`items-stretch`), CTA-less (the single page CTA sits below the grid). |
| `/dashboard` | Single content column, `max-w-3xl`. No sidebar in this phase — there is nothing to navigate to yet. A sidebar is Phase 3+'s decision, not a Phase 2 placeholder. |
| Form field order (`/login`) | Email → Password → CTA. |
| No | No modals, no drawers, no dialogs, no carousels, no toasts, no tooltips-as-only-explanation, no animation beyond `loader-circle` and default focus/hover transitions. The one confirmation this phase needs (plan downgrade) is an **inline two-step**, not a dialog. |

### Accessibility floor

- Every input has a visible `<label>`. Placeholder-as-label is a contract violation.
- Visible focus ring on every interactive element (`--ring`, ≥2px, 3:1 contrast) — including the plan cards, whose focus ring must render on the **card**, not on the visually-hidden radio.
- Full keyboard path through login and plan selection: tab order matches visual order, Enter submits, arrow keys move between plan radios.
- `<html lang="en">` (already set in the root layout).
- Every route sets a meaningful `<title>` through the root layout's `%s · EINORT` template — `Sign in · EINORT`, `Choose your plan · EINORT`, `Your store · EINORT`, `Your store is unavailable · EINORT`.
- The disabled read-only controls must still be **focusable and announced** with their reason — prefer `aria-disabled` + a no-op handler over bare `disabled` where the merchant needs to reach the explanation by keyboard.
