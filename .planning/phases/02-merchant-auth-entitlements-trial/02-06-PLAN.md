## Phase Goal

**As a** merchant, **I want to** sign in to a dashboard that knows which store is mine from my session alone and shows my plan and trial state, **so that** I can run my store knowing my subscription limits are enforced on the server, not just displayed in the UI.

<objective>
Close the second entry point. Better Auth's `organization` plugin registers 34 live endpoints under `/api/auth/organization/*` that the Phase 1 apex handler already serves, and four of them mutate tenant state with no gate: `update` (accepts a new `slug`), `delete`, `invite-member` and `add-member` (defaulting to 100 seats).

Purpose: SUB-01's staff limits and SUB-02's "checked on every relevant write" cannot be claimed while a Server Action wrapper is the only control, because a wrapper cannot intercept an HTTP route handler. `organizationHooks` and the `membershipLimit` function form are the only layer that sees these calls, and they must consult the same entitlement registry so the two layers cannot drift.
Output: the four hooks, the seat-limit function, and two isolation suites that exercise the raw endpoints.
</objective>
