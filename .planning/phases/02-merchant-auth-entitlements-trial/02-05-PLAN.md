## Phase Goal

**As a** merchant, **I want to** sign in to a dashboard that knows which store is mine from my session alone and shows my plan and trial state, **so that** I can run my store knowing my subscription limits are enforced on the server, not just displayed in the UI.

<objective>
Ship the D-06 plan switch and, with it, the first real proof that the write gate works: a merchant can change tier while the trial is active, and cannot change anything once it has expired.

Purpose: SUB-02 requires plan limits and trial state to be checked server-side on every relevant write; a plan switch is this phase's only real write, so it is where the gate is proven. D-06 requires the switch to be built now rather than deferred, and the CONTEXT addendum (OQ-3) fixes the answer for expired trials as no.
Output: `switchPlan`, `/dashboard/plan` in both its active and expired states, and the SUB-02 isolation suite.
</objective>
