## Phase Goal

Merchants outside the fashion segment get their own structurally distinct storefront, and the template library reaches 50 visually distinct variations (10 Starter / 15 Business / 25 Professional) that a stranger would not mistake for one another.

> Planner note: the ROADMAP `**Goal:**` line for Phase 5 is not in `As a … I want to … so that …` form. It is reproduced verbatim rather than invented. Run `/gsd mvp-phase 5` if the user-story framing is wanted.

<objective>
Give the template key the draft/published pairing every other column on `StorefrontTheme` already has, using a hand-edited `RENAME COLUMN` migration, and teach the two read paths to select the right column.

Purpose: `05-RESEARCH.md` Finding 4 establishes that `templateKey` is the one unpaired column on a model that pairs everything else, so a `switchTemplate` that writes it directly is a silent publish AND a structurally inconsistent render (old document, new variant map). Pitfall 1 establishes that Prisma's schema diff has no rename primitive and will emit `DROP COLUMN` + `ADD COLUMN … DEFAULT 'flagship-fashion'`, silently resetting every merchant — and that because every merchant is on the flagship today, **no runtime test can catch it**. The source-level control is therefore the real control.
Output: the split columns, the hand-edited migration, the applied schema push, the two updated read paths, and the migration-safety test.
</objective>
