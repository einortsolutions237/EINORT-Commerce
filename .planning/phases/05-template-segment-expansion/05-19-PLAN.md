## Phase Goal

Merchants outside the fashion segment get their own structurally distinct storefront, and the template library reaches 50 visually distinct variations (10 Starter / 15 Business / 25 Professional) that a stranger would not mistake for one another.

> Planner note: the ROADMAP `**Goal:**` line for Phase 5 is not in `As a … I want to … so that …` form. It is reproduced verbatim rather than invented. Run `/gsd mvp-phase 5` if the user-story framing is wanted.

<objective>
Add the "Change template" capability to the existing storefront editor: a rail row, a picker panel, a destructive confirm dialog, and the state plumbing that repaints the preview without a reload.

Purpose: D-08 requires a switch action inside the editor, constrained to the merchant's current plan tier. D-09 requires an explicit warning before the switch commits, because a different template can have an entirely different section list with no sensible mapping from the old one. 05-UI-SPEC settles the surrounding questions: the panel adds no save or publish button and no status pill of its own, because `switchTemplate` is a completed persisted write and the existing `PublishBar` already has the branch for saved-but-unpublished.
Output: four files — one new panel, three amended editor files.
</objective>

| editor client → `switchTemplate` | reachable by direct POST; the panel's card state is a courtesy only |
| editor shell → preview iframe | the variant map crosses an origin boundary by postMessage |
| downgraded merchant → an above-tier current template | the card must be visible but must never be re-selectable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-70 | Elevation of Privilege | a stale client posting an out-of-tier key | mitigate | `assertTemplateAccess` in the action refuses before any DB call; the panel surfaces the refusal as a non-destructive alert with a plan link |
| T-05-71 | Repudiation | a downgraded merchant re-selecting a retained above-tier template | mitigate | The current-template card is inert; clicking it opens no dialog and calls no action |
| T-05-72 | Tampering | a switch reaching customers before publish | mitigate | `switchTemplate` writes draft columns only; the publish bar renders saved-but-unpublished and the merchant must still press Publish once |
| T-05-73 | Tampering | forged postMessage carrying a variant map | mitigate | The canvas's origin comparison runs first and `sectionVariantsSchema` validates the field (plan 05-10); the shell posts only to the server-computed preview origin |
| T-05-74 | Information Disclosure | `server-only` registry reaching the editor client bundle | mitigate | Tiles and the variant map are assembled in the RSC; `npm run build` and the marker-boundary test both gate it |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | Zero package installs this phase; `alert-dialog`, `radio-group`, `card`, `badge` and `tooltip` are already present |
