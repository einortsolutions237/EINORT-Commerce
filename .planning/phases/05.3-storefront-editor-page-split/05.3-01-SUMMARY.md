## Decisions Made

- **EDIT-02/EDIT-03 left "Pending" in REQUIREMENTS.md.** This plan's frontmatter lists both requirement IDs, but this plan only lands shared, non-route-file infrastructure — the actual page split those requirements track (the Editor route move, the new Themes page) happens in `05.3-02`/`05.3-03`. Ticking them complete now would repeat the exact TMPL-06 premature-completion mistake already documented and corrected earlier in this project (STATE.md, Phase 05.1). Completion is deferred to the `05.3-04` phase gate.
- **Worktree environment bootstrap, not committed.** This isolated worktree ships with no local `node_modules` — Node's own module resolution (used by `tsc`, the Prisma CLI, and ESLint) transparently walks up to the parent repo's shared `node_modules`, but two tools with their own hermetic/file-based resolution do not: Turbopack refuses to resolve `next` above the nearest lockfile (the worktree root itself, since `package-lock.json` is checked out there), and Vitest's `server-only` alias target is a literal `file://` path computed relative to `vitest.config.ts`. Generated three small, already-gitignored artifacts to unblock verification: (1) `src/generated/prisma/**` via `npx prisma generate` with dummy `DATABASE_URL`/`DIRECT_URL` connection strings (schema generation does not connect to a live database), (2) `next-env.d.ts` (the standard, deterministic two-line Next.js boilerplate — needed for the `next/image` module's `.png` type declarations and, incidentally, a partial `next build` attempt against dummy env vars had already produced enough of `.next/types/**` to resolve the ambient `PageProps`/`LayoutProps` names before Turbopack's own hermetic-resolution failure aborted the build), and (3) an empty `node_modules/server-only/empty.js` stub matching the real `server-only@0.0.1` package's own marker-package shape. None of these three are tracked by git; all match pre-existing `.gitignore` entries (`src/generated/`, `next-env.d.ts`, `node_modules/`).
