## Phase Goal

> **ROADMAP `**Goal:**` verbatim (this phase carries no `**Mode:** mvp` line in ROADMAP.md, so MVP-mode vertical-slice task-ordering does not apply — this is standard phase planning):**
>
> Split the merchant dashboard's storefront editor from its current single-screen, single-route design into two genuinely separate pages/routes -- a dedicated "Themes" page for browsing/switching templates, and a dedicated full-screen "Editor" page for section/block editing only -- matching the navigational separation in Shopify's own admin, layout/structure only, no new capabilities (existing fixed-five-sections, no-add/remove behavior from Phase 4's locked D-05 preserved exactly).

**This plan's role:** the shared, non-route-file infrastructure every other plan in this phase needs before it can typecheck or pass its own contract test: the new copy the leave-guard dialog and Themes page will reference, the sidebar's repointed destination and its paired test, and the three `revalidatePath` calls whose targets change (one of them from one path to two). Plans `05.3-02` (Editor route move) and `05.3-03` (new Themes page) both depend on this plan for the `strings.editor` keys they reference in JSX — if they ran first, `npm run typecheck` would go red on an undefined key.

<objective>
Land every cross-cutting, non-route-file change this phase needs in one wave: seven new `strings.editor` copy keys, the sidebar's `href` repoint (paired, same-commit, with the test that enforces it), and the `revalidatePath` argument fix across `publishStorefront`, `discardDraft` and `switchTemplate` — the last of which needs two calls, not a one-to-one rename, because it now fires from a different page than the one whose state it must refresh.

Purpose: `05.3-RESEARCH.md`'s own hardcoded-route inventory names exactly five functional call sites (sidebar href, three `revalidatePath` args, one test literal) plus two doc comments, and Pitfall 1 ("the dead `revalidatePath`") is named as the single most likely silent defect in the whole phase — a stale path produces no error, no red test, only a status pill that quietly stops telling the truth. Landing all of it in one plan, ahead of the route moves, means the two route-moving plans typecheck clean the first time they run rather than discovering a missing string key mid-move.
Output: `strings.editor` carries the seven new keys the leave-guard dialog and the Themes page will render; the sidebar and its test agree on `/dashboard/storefront`; `publishStorefront`/`discardDraft` point at `/dashboard/storefront/editor`; `switchTemplate` points at both new paths.
</objective>
