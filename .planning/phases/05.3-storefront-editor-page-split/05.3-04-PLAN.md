## Phase Goal

> **ROADMAP `**Goal:**` verbatim (this phase carries no `**Mode:** mvp` line in ROADMAP.md, so MVP-mode vertical-slice task-ordering does not apply — this is standard phase planning):**
>
> Split the merchant dashboard's storefront editor from its current single-screen, single-route design into two genuinely separate pages/routes -- a dedicated "Themes" page for browsing/switching templates, and a dedicated full-screen "Editor" page for section/block editing only -- matching the navigational separation in Shopify's own admin, layout/structure only, no new capabilities (existing fixed-five-sections, no-add/remove behavior from Phase 4's locked D-05 preserved exactly).

**This plan's role:** the phase gate. `05.3-01` built the shared infrastructure, `05.3-02` moved the Editor, `05.3-03` built the Themes page — this plan proves the three fit together: no dead route reference survives anywhere, the automated suite is green, D-B's "layout/structure only" boundary was actually honored and not just intended, and the six behaviors no test in this codebase's `environment: "node"` unit project can see have been exercised by a human.

<objective>
Run the phase's complete verification surface — the dead-route grep gate `05.3-RESEARCH.md` names as Pitfall 1's mitigation, the full automated suite, and an explicit D-B scope-creep check — then hand the six manual UI behaviors to the developer for sign-off before the phase is considered done.

Purpose: this phase's dominant risk is silent, not loud — `05.3-RESEARCH.md`'s own "What breaks silently" section ranks a stale `revalidatePath` argument and a dirty-draft navigation loss as the two most likely defects, and neither produces a failing automated test if missed. This plan is where that gap gets closed by an explicit gate rather than by hoping the first three plans got it right.
Output: a phase-level pass/fail on the grep gate, the full suite, and a signed-off manual verification pass — or a specific, named defect to fix before the phase closes.
</objective>
