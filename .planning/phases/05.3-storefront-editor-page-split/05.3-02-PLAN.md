## Phase Goal

> **ROADMAP `**Goal:**` verbatim (this phase carries no `**Mode:** mvp` line in ROADMAP.md, so MVP-mode vertical-slice task-ordering does not apply — this is standard phase planning):**
>
> Split the merchant dashboard's storefront editor from its current single-screen, single-route design into two genuinely separate pages/routes -- a dedicated "Themes" page for browsing/switching templates, and a dedicated full-screen "Editor" page for section/block editing only -- matching the navigational separation in Shopify's own admin, layout/structure only, no new capabilities (existing fixed-five-sections, no-add/remove behavior from Phase 4's locked D-05 preserved exactly).

**This plan's role:** move the seven files that make up today's single-route editor into the new `storefront/editor/` segment, and make the one behavioral change the split requires of them — deleting the in-page template-switch rail branch and replacing it with a guarded link to the new Themes page, closing the dirty-draft data-loss gap that a real client-side navigation opens where a `useState` push/pop previously could not lose anything.

<objective>
`git mv` all seven files from `src/app/(dashboard)/dashboard/storefront-editor/` into `src/app/(dashboard)/dashboard/storefront/editor/`. Four move byte-identical (`settings-panel.tsx`, `field-renderer.tsx`, `publish-bar.tsx`, `loading.tsx`). Three carry a bounded, named edit: `page.tsx` loses the `templates` prop and `editorTemplateTiles`; `editor-shell.tsx` loses the `changeTemplate` rail branch, `handleTemplateSwitched`, and the `templates` prop, gains the R-1 full-bleed wrapper and the R-4 leave-dialog's state/`AlertDialog`; `section-list.tsx`'s `Change template` row becomes a guarded `<Link>` instead of a rail push/pop button.

Purpose: this is the highest-risk plan in the phase — `editor-shell.tsx` is 899 lines and is EDIT-02's entire behavioral surface, covered by exactly one automated test suite (`editor-reducer.test.ts`, which tests the reducer `editor-shell.tsx` wraps, not the component itself, since the `unit` project runs on `environment: "node"` with no jsdom). Every deletion in this plan is load-bearing and every one is named explicitly in `05.3-RESEARCH.md` Focus 1 and `05.3-PATTERNS.md`'s file-by-file delta — there is no room for an "obvious cleanup" that isn't one of the named deletions.
Output: a working `/dashboard/storefront/editor` route, `src/app/(dashboard)/dashboard/storefront-editor/` fully empty of these seven files, and a new dirty-draft navigation guard that did not exist before this phase.
</objective>
