# Phase 05.3: Storefront Editor Page Split - Context

**Gathered:** 2026-09-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Split the merchant dashboard's storefront editor from its current single-screen, single-route design (`src/app/(dashboard)/dashboard/storefront-editor/` — one client component, `editor-shell.tsx`, with a 320px left rail that push/pops between a section list, a settings panel, and a template-switch panel, alongside a live-preview iframe) into two genuinely separate pages/routes:

1. A dedicated **"Themes" page** for browsing and switching templates — building on the template-picker/current-template-card work already shipped in quick task 260908-bv1.
2. A dedicated, full-screen **"Editor" page** for section/block editing only (section list, settings panel, live preview).

This matches the navigational separation in Shopify's own admin, where "Online Store" (theme library) and the theme editor are distinct pages — the user demonstrated this via a live Shopify screenshot of their theme editor (persistent left section list, live preview canvas, top toolbar with theme name/draft status, undo/redo controls, Publish/Save).

Explicitly NOT in scope: any change to what a merchant can DO in either surface — this phase moves where existing capability lives, not what it does.

</domain>

<decisions>
## Implementation Decisions

### Page structure
- **D-A:** Two separate pages/routes, not a single-screen layout restructuring. This is real route-splitting — a dedicated Themes page and a dedicated full-screen Editor page — not just a visual restyle of the existing single-route rail.

### Scope of capability
- **D-B:** Layout/structure only for this phase — NO new capabilities. Explicitly OUT of scope: Header/Template/Footer section grouping, "Add section" (add/remove sections), and undo/redo. All three were shown in the user's Shopify reference screenshot and explicitly deferred by the user to a future phase ("In the future all this new capabilities will be added but for now let's go with... Layout/structure only"). The existing fixed-five-sections, no-add/remove behavior (Phase 4's locked D-05 decision in `04-UI-SPEC.md`) must be preserved exactly.

### Claude's Discretion
- Exact navigation mechanism between the two new pages (tab pair, back link, sidebar entries, breadcrumb) — grounded in this project's existing dashboard nav conventions (`src/components/app-sidebar.tsx`), resolved at UI-SPEC.
- Whether Publish/Save/Discard (currently in `publish-bar.tsx`, spanning both panes on the single existing screen) live on the Editor page only, or need any presence on the Themes page — given `switchTemplate` already exists as a separate server action from the section-editing save/publish flow, research should determine whether template-switching needs its own distinct commit flow or reuses the existing one.
- What server/client state currently colocated in `editor-shell.tsx` (899 lines) needs to be duplicated, lifted, or fetched independently per route once split.
- Whether `change-template-panel.tsx` (just restructured in quick task 260908-bv1) moves wholesale into the new Themes page or needs adaptation for a full-page (vs. 320px-rail) context.
- Exact route paths/URL structure for the two new pages.

</decisions>
