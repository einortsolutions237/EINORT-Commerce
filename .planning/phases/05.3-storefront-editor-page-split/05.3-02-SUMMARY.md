## Decisions Made
- `handleTemplateSwitched`'s 27-line staleness-compensation logic was deleted wholesale rather than ported anywhere — the split makes the race it guarded against structurally impossible (the template switch and the editor visit are now two separate requests to two separate pages)
- The leave-confirmation `AlertDialog` lives in `editor-shell.tsx` (the state owner), not `section-list.tsx` — `section-list.tsx` receives a fully-closed `onChangeTemplateNavigate` handler and never reads `state.dirty` itself, so its pre-existing "owns no draft state and must never grow any" header invariant holds by construction, not by discipline
- Scope of the new guard is deliberately narrow (the `Change template` link only) — sidebar links and browser back/forward remain unguarded, matching pre-existing behavior; this is recorded as an accepted, deliberate gap in the plan's own threat model (T-05.3-06), not something this plan needed to close
