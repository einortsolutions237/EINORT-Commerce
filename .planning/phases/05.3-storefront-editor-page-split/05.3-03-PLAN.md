## Phase Goal

> **ROADMAP `**Goal:**` verbatim (this phase carries no `**Mode:** mvp` line in ROADMAP.md, so MVP-mode vertical-slice task-ordering does not apply — this is standard phase planning):**
>
> Split the merchant dashboard's storefront editor from its current single-screen, single-route design into two genuinely separate pages/routes -- a dedicated "Themes" page for browsing/switching templates, and a dedicated full-screen "Editor" page for section/block editing only -- matching the navigational separation in Shopify's own admin, layout/structure only, no new capabilities (existing fixed-five-sections, no-add/remove behavior from Phase 4's locked D-05 preserved exactly).

**This plan's role:** build the new "Themes" half of the split — a page that did not exist before this phase. It is not a rewrite: `change-template-panel.tsx` already contains nearly all of this page's real content (spotlight card, switchable grid, destructive confirm dialog) and has zero relative imports, so most of the work is `git mv` plus rail-specific stripping (back row, `px-4 py-6` padding) and page-appropriate additions (an `<h1>`, the R-3 two-column spotlight composition, a success toast instead of a callback into a parent shell that no longer exists).

<objective>
Create `src/app/(dashboard)/dashboard/storefront/page.tsx` (the Themes RSC) and `src/app/(dashboard)/dashboard/storefront/loading.tsx` (its skeleton) from scratch, and `git mv` `change-template-panel.tsx` into `src/app/(dashboard)/dashboard/storefront/themes-browser.tsx` with a rename (`ChangeTemplatePanel` -> `ThemesBrowser`) and a bounded set of edits: delete the back row and its rail-tight padding, promote the panel title to the page's `<h1>`, replace the `onSwitched` callback with a `toast.success` + `router.push` action, and compose `<CurrentTemplateCard>` into the R-3 two-column spotlight row with its new `sizes` prop.

Purpose: `05.3-RESEARCH.md` Focus 6 traces every line of `change-template-panel.tsx` and classifies exactly which are rail-specific (delete) versus portable (keep unchanged) — including the finding that `<TemplatePicker>`'s `@container` grid needs zero CSS change to re-flow correctly at page width, because Phase 5.1 already built it for exactly this kind of container-width portability. `05.3-UI-SPEC.md` R-3 resolves the one genuinely new layout decision (the spotlight card's composition) that research explicitly declined to make unilaterally.
Output: a working `/dashboard/storefront` route showing the spotlight + grid + confirm-dialog + success-toast flow, `current-template-card.tsx` widened to accept a caller-supplied `sizes`, and `change-template-panel.tsx` fully retired from its old location.
</objective>
