## Phase Goal

ROADMAP `**Goal:**` (verbatim — see the planner note in the return, this phase's goal is not in `As a / I want to / so that` form and has two actors): *A merchant can run their business day-to-day from a dashboard that surfaces what needs attention, and the platform owner can operate and support the pilot fleet of stores from a pilot-scoped Super Admin surface — including a direct messaging channel to every merchant and the ability to verify their subscription payments through it.*

**This plan's vertical slice:** the platform owner's account can be minted and is recognised by the server; logging in with it resolves `/admin` as the destination. Nothing else on the platform can reach admin identity.

<objective>
Build the admin trust boundary before any admin surface exists: `requireAdminContext()`, `adminAction()`, the out-of-band bootstrap script that mints the one admin account, and D-05's server-side post-login role routing.

Purpose: `User.platformRole` has existed since Phase 1 with `input: false` and no reader and no writer. This plan makes it load-bearing without ever opening a public write path to it (RESEARCH Pitfall 6). Every later plan's gate is this module.
Output: `src/server/admin/**` (2 modules), `scripts/promote-admin.ts`, role-aware login, and the two contract-test obligations that must land with them.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → `/admin/*` | An unauthenticated prober trying to establish whether the surface exists |
| merchant session → admin identity | A legitimate but lower-privilege session reaching for a higher-privilege DAL |
| signup/update request body → `User.platformRole` | Client-supplied data attempting to mint an administrator |
| CLI operator → `prismaBase` | The bootstrap script writes the highest-privilege field in the product |
