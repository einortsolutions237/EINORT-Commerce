## Phase Goal

ROADMAP `**Goal:**` for Phase 6, verbatim: *A merchant can run their business day-to-day from a dashboard that surfaces what needs attention, and the platform owner can operate and support the pilot fleet of stores from a pilot-scoped Super Admin surface — including a direct messaging channel to every merchant and the ability to verify their subscription payments through it.*

**This plan's slice:** it delivers no user-visible capability on its own. It is deliberately front-loaded because 06-UI-SPEC.md § Copy modules and RESEARCH Pitfall 10 both require the copy to be authored in one pass **before** the components — otherwise ten later plans each invent a fragment of the voice and the two-audiences rule collapses. Every later plan in this phase reads these files and writes none of them.

<objective>
Author the complete copy surface for Phase 6 in two new string modules plus a small set of new keys in the existing index, following the `marketing.ts` / `flagship.ts` precedent.

Purpose: `src/lib/strings/index.ts` is already ~1,600 lines and this codebase's contract tests scan `.tsx` source for prose-shaped literals. Authoring copy first makes every later component a lookup, not a decision, and enforces 06-UI-SPEC.md's two-audiences rule structurally (a string that would have to be shared between merchant and admin has to be duplicated on purpose, which is visible in review).
Output: `src/lib/strings/admin.ts`, `src/lib/strings/support.ts`, and new keys spread into `src/lib/strings/index.ts`.
</objective>
