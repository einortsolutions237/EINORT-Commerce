## Phase Goal

ROADMAP `**Goal:**` for Phase 6, verbatim: *A merchant can run their business day-to-day from a dashboard that surfaces what needs attention, and the platform owner can operate and support the pilot fleet of stores from a pilot-scoped Super Admin surface — including a direct messaging channel to every merchant and the ability to verify their subscription payments through it.*

**This plan's vertical slice:** the platform owner can see the pilot fleet — every store, its plan, its live domain, and its size — and open any one of them. Suspending arrives in plan 06-14; this slice is the view half of ADM-01 plus all of ADM-03's domain-status clause.

<objective>
Build `/admin`'s merchants list and the per-merchant detail page, with domain status derived rather than stored.

Purpose: ADM-03 asks for "domain status across tenants". There is no `Domain` model, no `customDomain` column and no DNS state in the schema — every store's domain today is exactly `{slug}.{ROOT_DOMAIN}` and its status is a function of `Organization.status`. D-21 therefore makes this a column and a card, not a page, and the derivation lives in one exported function so Phase 15 replaces a function instead of a JSX expression.
Output: a pure domain module with its unit test, a reusable domain cell, two cross-tenant queries, and two pages.
</objective>

**D-21 / § D:** domain status is a **column** on `/admin` and a **card** on `/admin/merchants/[id]`. There is **no** `/admin/domains` route. Build it as one `<DomainCell>` that renders a **list** of domains; today the list always has exactly one entry, and Phase 15 adds entries without restructuring the cell. Two chip states only — `Live` (`outline-success`, `globe`) when the org is `active` and the store is published, `Offline` (`secondary`, `globe-lock`) otherwise. A third state would imply DNS state this phase cannot observe. **Do not** write "custom domain", "coming soon", or a disabled "Add domain" button: unshipped scope is not a product surface.

**§ C1 row actions:** a `dropdown-menu` behind an `ellipsis` icon-button, never a bare button in a dense row. This plan ships two items — `View store` (opens the storefront in a new tab) and `Open support thread`. **`Open support thread` is added by plan 06-12, and `Suspend store`/`Restore store` by plan 06-14.** Ship only the items whose destinations exist; a menu item pointing at a 404 is worse than an absent one. Structure the menu as a data array so each later plan appends one row.

**§ C1 layout:** `table` at `md`+, **stacked cards below `md`, never horizontal scroll**. Content column `max-w-6xl` (the admin ledgers carry more columns than a merchant list). No search box at pilot scale — an unimplemented search input is worse than none.

**Copy** comes from `strings.admin.merchants`, `strings.admin.merchantDetail`, `strings.admin.domain`, `strings.admin.storeStatus` (plan 06-02). This plan authors none.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL path parameter `[id]` → a cross-tenant query | The admin surface is cross-tenant by design, but the id is still untrusted input |
| page component → `adminDb` | The ESLint zone is `src/server/admin/**`, not `src/app/admin/**` |
| derived domain status → what the owner believes is live | A status chip that lies is worse than no chip |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-31 | Information Disclosure | `/admin/merchants/[id]` with a probed id | mitigate | Every page calls `requireAdminContext()` itself, so an unauthorized caller never reaches the query; a non-matching id calls `notFound()`, which is the same response an unauthorized caller gets |
| T-06-32 | Elevation of Privilege | `adminDb` imported from a page component | mitigate | Pages call into `src/server/admin/**`; grep-asserted that no `src/app/admin/**` file imports the client, and `eslint.config.mjs` is unchanged (STATE.md's #1 milestone risk is widening this fence) |
| T-06-33 | Information Disclosure | an unpredicated cross-tenant list read | accept | Cross-tenant reads are the requirement (ADM-02/ADM-03); the control is `requireAdminContext()` plus the import fence, not a predicate |
| T-06-34 | Tampering | a `domainStatus` column arriving later | mitigate | Derived pure function only, with a header stating that a stored column would immediately be a second source of truth with no writer |
| T-06-35 | Information Disclosure | the storefront `external-link` from the admin console | mitigate | `rel="noopener"` on every new-tab link so the opened merchant storefront cannot reach back through `window.opener` into the highest-privilege session in the product |
| T-06-SC | Tampering | shadcn / npm installs | mitigate | Zero components added, zero packages |
</threat_model>
