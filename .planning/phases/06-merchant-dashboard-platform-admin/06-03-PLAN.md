## Phase Goal

ROADMAP `**Goal:**` for Phase 6, verbatim: *A merchant can run their business day-to-day from a dashboard that surfaces what needs attention, and the platform owner can operate and support the pilot fleet of stores from a pilot-scoped Super Admin surface — including a direct messaging channel to every merchant and the ability to verify their subscription payments through it.*

**This plan's slice:** the persistence layer for the thread and the subscription claim, applied end to end — schema, generated client, live database, registry, and both isolation fixtures — so that every later plan can write a row without a second migration.

**Resolved discretion decisions carried into this schema:**
- SUB-03 is a **new** `SubscriptionPaymentClaim` model, not a discriminated `PaymentClaim` (RESEARCH Q1: the composite FK to `Order` cannot be made optional cleanly, the uniqueness scope is per-tenant vs global, and a second writer on `PaymentClaim.status` would break the ORD-02 source-scanning guard).
- There is **no** `SupportThread` model (RESEARCH Q6: D-12 leaves it no state to carry, and its only columns would be the denormalized counters `src/server/claims/queries.ts` argues against by name).
- `SubscriptionPaymentClaim.referenceNormalized` is **globally** unique, not per-tenant (RESEARCH A1): the payee is one platform account, so the same reference twice is the same payment twice.
- `Organization.subscriptionCurrentPeriodEnd` is **stored and displayed only**. `resolveEntitlements` is NOT taught to expire on it in this phase — that is a `canWrite` semantics change touching every gated action and is flagged in STATE.md as `KD-V2-02`, the milestone's largest hidden cost. Record the deferral in the schema comment.
- `SupportAttachment` carries `kind`, `contentType`, `byteSize`, and **nullable** `width`/`height` from day one so plan 06-13's PDF path (D-22) needs no second migration. PDFs have no raster dimensions.

**Existing enum re-export pattern:** `src/server/db/enums.ts` re-exports generated enums (`ClaimStatus`, `OrderState`, `PaymentOperator`) so feature code never imports `@/generated/prisma*` directly — that import is ESLint-banned outside `src/server/db/**`.
