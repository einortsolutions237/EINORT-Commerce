## Phase Goal

ROADMAP `**Goal:**` for Phase 6, verbatim: *A merchant can run their business day-to-day from a dashboard that surfaces what needs attention, and the platform owner can operate and support the pilot fleet of stores from a pilot-scoped Super Admin surface — including a direct messaging channel to every merchant and the ability to verify their subscription payments through it.*

**This plan's vertical slice:** the platform owner can review and act on any customer→merchant payment claim on the platform, from one table, one tap per decision. ADM-02 complete.

`src/server/admin/claims.ts` (plan 06-07) exports `listOrderClaimsForAdmin`, `pendingOrderClaimCount`, `adminConfirmOrderClaim({ claimId, actorUserId })` and `adminRejectOrderClaim({ claimId, reason, actorUserId })`. `src/server/admin/action.ts` (plan 06-01) exports `adminAction({ schema, handler })`, which resolves `requireAdminContext()` before parsing and calls `notFound()` on any authorization failure.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `src/server/admin/actions.ts` | Every Server Action is a public endpoint reachable by direct POST without loading the page |
| `searchParams` filters → a cross-tenant query | URL-supplied filter values reach a query with no tenant predicate |
| R2 derivative URL → the browser | Claim screenshots are capability URLs served without authentication |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-41 | Elevation of Privilege | direct POST to the confirm/reject actions | mitigate | Both are `adminAction`-wrapped: `requireAdminContext()` resolves and `notFound()`s before the payload is parsed; the actor id comes from the session, never from the payload |
| T-06-42 | Tampering | a client-supplied `actorUserId` or `status` | mitigate | The Zod schemas accept only `claimId` and `reason`; nothing else is readable from the request |
| T-06-43 | Tampering | double-tap confirm across two admin tabs | mitigate | The optimistic lock lives inside the transaction in `src/server/admin/claims.ts` (plan 06-07); the optimistic UI is presentation only and the server refusal wins |
| T-06-44 | Information Disclosure | a storage key or presigned URL leaking into the client bundle | mitigate | `publicUrlFor` and `formatXaf` run server-side and the island receives finished strings; grep-asserted that neither appears in the island |
| T-06-45 | Information Disclosure | `searchParams` used to widen a query | accept | The admin ledger is cross-tenant by requirement (ADM-02); filters narrow, never widen, and authorization is `requireAdminContext()`, not a predicate |
| T-06-46 | Information Disclosure | publicly readable claim screenshots containing PII | accept | Established Phase 3 precedent: an unguessable v4-UUID capability URL served from `R2_PUBLIC_BASE_URL` with no auth. Recorded as an explicit acceptance here rather than rediscovered later |
| T-06-SC | Tampering | npm installs | mitigate | Zero packages, zero shadcn components added |
</threat_model>
