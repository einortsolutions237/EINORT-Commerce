## ⚠️ READ THIS FIRST — SCOPE AND WHAT MUST NOT CHANGE

This phase redesigns exactly **one route**: the apex root page (`src/app/page.tsx`, unauthenticated, statically rendered). It replaces the current 3-element placeholder with the five D-04 bands plus one minimal top lockup.

| Boundary | Rule |
|---|---|
| Route | `/` (apex hostname only). `src/proxy.ts` already keeps this unreachable from a storefront subdomain — **do not touch the proxy.** |
| Layout | `src/app/layout.tsx` — **no change.** No new `<head>` logic, no `ThemeProvider`, no header/nav component added to the shared layout. The top lockup lives inline in `page.tsx` only, because no other apex surface (`/login`, `/signup`) wants it. |
| Design system | Blue/slate only (D-06 — **no gold**), extending `.planning/design-references/EINORT-COMMERCE-FRONT-END-MERCHANT-PLATFORM.md`, exactly as every other apex page (`/login`, `/signup`, `/dashboard`) already does. This page invents zero new tokens in `globals.css`. |
| Forms | **None.** No email capture, no POST of any kind (D-04, confirmed by `05.2-RESEARCH.md` § Security Domain V5). Every interactive element is a `<Link>` to `/signup` or `/login`. |
| Copy | Every visible string lives in `src/lib/strings/marketing.ts` (new), spread into `strings.root` per `05.2-RESEARCH.md` Pattern 1. Zero inline JSX prose. |

**The six build-failing guards this page must never trip** (verbatim from `05.2-RESEARCH.md` § Common Pitfalls — restated here because a design decision that ignores one of these is not a valid design decision):

1. No literal colour (`tests/unit/surface-token-isolation.test.ts` ban #1) — hex/oklch/rgb, none, ever.
2. No Tailwind palette utility (ban #2) — no `slate-*`, `blue-*`, etc.; semantic tokens only.
3. No `variant="gold"` anywhere on this page (`tests/unit/dashboard-nav.test.ts`) — D-06.
4. No `brand-accent` token (ban #6) — that family is storefront-only and resolves to nothing here anyway.
5. No `preview-assets` / `PREVIEW_PLACEHOLDER_PHOTOS` reference anywhere under `src/` (`tests/unit/preview-photo-isolation.test.ts`) — D-05's whole reason for existing.
6. No `data-surface="storefront"` — this page is Surface A (merchant platform palette), not Surface B.

## Spacing Scale

Inherited verbatim from the platform-wide seven-step scale (`04-UI-SPEC.md`/`05-UI-SPEC.md`/`05.1-UI-SPEC.md`). **Zero new tokens.**

| Token | Value | Usage on this page |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gap inside the tier-free lockup, gap between step numeral and its connecting rule |
| sm | 8px | Gap between H2 and its icon badge (vertical); logo-to-nav-link gap in the top lockup |
| md | 16px | Heading → body paragraph gap; mobile section side gutter (`px-4`) |
| lg | 24px | Body → honest-constraint-line gap is **not** this — see § Honest-Constraint Treatment. Gap between hero copy block and CTA block on mobile. |
| xl | 32px | Desktop section side gutter (`px-8`); hero grid gap on `lg+`… *(corrected — see exception table)* |
| 2xl | 48px | Icon/step badge diameter (`size-12`); hero grid column gap on `lg+` (`lg:gap-12`) |
| 3xl | 64px | **All** section band vertical padding (`py-16`), uniformly, top lockup excluded |

**Exceptions (layout constants, not scale tokens — same category as `05.1-UI-SPEC.md`'s own exception table):**

| Exception | Value | Why |
|---|---|---|
| Top lockup vertical padding | `py-6` (24px, `lg`) | The lockup is chrome, not a content band; giving it the full `3xl` band rhythm would read as a seventh section. |
| Hero image aspect / dimensions | `width={1280} height={800}` (16:10) | Matches the 05.1 preview-pipeline derivative exactly — no re-crop, no letterbox. |
| Icon/step badge diameter | `size-12` (48px = `2xl`, reused as a diameter, not a gap) | Large enough that a `size-6` (24px) lucide icon or a two-digit-safe numeral sits centred with visible tint around it; small enough not to compete with the section H2. |
| Content column widths | `max-w-2xl` (672px, hero-no-image / final CTA) · `max-w-3xl` (768px, each differentiator) · `max-w-5xl` (1024px, top lockup / hero-with-image / how-it-works) | Named Tailwind widths, not arbitrary values — the same three widths already in use elsewhere in the app (`login`/`signup` use `max-w-md`; onboarding uses the 05.1-widened `max-w-5xl`). |

**Corrects `05.2-RESEARCH.md`'s own code example:** its semantic-token snippet uses `py-20` (80px). 80px is not in the closed seven-step scale. This page uses `py-16` (`3xl`, 64px) for every section band instead — deliberate, not an oversight (same category of correction `05.1-UI-SPEC.md` made to `gap-5`).

## Color

Inherited from `:root` (Surface A — blue/slate). **Zero new colour tokens.** D-06 is absolute: **no gold anywhere on this page.**

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--background` | `oklch(0.984 0.003 247.9)` slate-50 | Every "light" section band, the top lockup, the page field |
| Secondary (30%) | `--muted` / `--muted-foreground` | `oklch(0.968 0.007 247.9)` slate-100 / `oklch(0.554 0.041 257.4)` slate-500 | Alternate section band fill (`bg-muted/40`), icon/step badge tint background, all supporting body text |
| Accent (10%) | `--primary` | `oklch(0.546 0.215 262.9)` brand-600 | See reserved-for list below — this is the entire accent budget for the page |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | **Not used.** This page has no error state, no form, nothing destructive. |
| Derived | `--ring` | `oklch(0.623 0.188 259.8)` brand-500 | Focus ring on every interactive element (non-discretionary) |

**Accent (`--primary`) reserved for exactly these things — no additions:**
1. The primary CTA button fill (`Button` default variant), used identically in the hero and the final CTA — **the same button, twice**, not two separate uses (Finding 4).
2. The differentiator icon badge (`bg-primary/10 text-primary`) — one visual treatment, applied 3 times (once per differentiator), not three separate decisions.
3. The how-it-works step numeral colour (`text-primary`) and its connecting hairline, reusing the same badge treatment for visual consistency with #2 rather than inventing a fourth pattern.
4. (Derived, non-discretionary) the focus ring via `--ring`.

**Accent is explicitly NOT for:** the top-lockup or final-CTA "Sign in" text links (U-12 — kept `text-foreground` so neither ever reads as a second CTA), the honest-constraint line (kept `text-foreground`, not `text-primary` — it is elevated by ink, not by brand colour, see below), any section background (bands alternate `bg-background`/`bg-muted/40` only), the top lockup's wordmark.

**Gold budget:** untouched. `variant="gold"` appears exactly zero times in this page's source, preserving `tests/unit/dashboard-nav.test.ts`'s exactly-twice, sidebar-only contract.

### Honest-Constraint Treatment (D-01's core mechanism, made visible)

Per `05.2-RESEARCH.md` Finding 3, the "no card gateway", "no automatic settlement", "no verification step" lines are the page's competitive advantage, not a caveat. The visual treatment must read as confident, not apologetic:

| Rule | Contract |
|---|---|
| Position | Directly beneath the differentiator's body paragraph, same section, `mt-3` (tighter than the `md` heading→body gap — it reads as a continuation of the thought, not a new block) |
| Colour | **`text-foreground`** (full ink) — one step *more* prominent than the muted body paragraph above it, not less. This is a deliberate hierarchy inversion: normally a supporting detail is muted; this one is elevated because it is the sentence doing the actual persuading. |
| Never | A bordered callout box, a warning/info icon, italics, a background tint, a "Note:" or "Disclaimer:" lead-in, `text-muted-foreground`, `text-destructive`, or any yellow/amber colour. Every one of those reads as an apology or a legal footnote — exactly what Finding 3 warns against. |
| Weight | Same as the body paragraph (400) — no bold. Prominence comes from colour contrast alone, not from shouting. |

## Responsive Behavior

Mobile-first throughout — this market's traffic is phone-first on 3G/4G Android (`05.2-RESEARCH.md` Finding 5). The default (no-prefix) Tailwind classes above already describe the mobile layout; breakpoints only ever *add* columns/width, never remove content.

| Breakpoint | What changes |
|---|---|
| Base (< 640px) | Single column everywhere. Hero: centred stack (image, if present, renders below the CTA block, not above it — text and CTA must be reachable within the first screenful even if the image is heavy). How-it-works: 3 stacked steps, `gap-12` between them. |
| `sm:` (≥640px) | How-it-works becomes a 3-column grid (`sm:grid-cols-3`). No other band changes shape here. |
| `lg:` (≥1024px) | Hero becomes a 2-column grid **only if** the manifest has an entry (`lg:grid-cols-2`). Hero H1 steps to `lg:text-6xl`. |
| Touch targets | The 44px floor (`min-h-11`) applies to both `Button` instances (hero + final CTA), exactly as the current placeholder page already enforces. Text links (`Sign in`, both places) are not buttons and are not forced to 44px — this matches the existing, reviewed `/login`/`/signup` cross-link precedent. |
| Weight budget | One hero image (when present, one file, lazy-eligible-but-eager per Pattern 4), one static logo import, `lucide-react` inline SVGs (zero network requests). No video, no carousel, no animation library — unchanged from Standard Stack's explicit rejection list. |
