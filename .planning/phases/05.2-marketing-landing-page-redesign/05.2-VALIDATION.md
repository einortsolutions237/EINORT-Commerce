# Phase 05.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.10, `unit` project (`environment: "node"`, `server-only` aliased to a stub). There is no DOM environment and no component-testing library in this project — every UI-level guarantee is asserted by source-scanning tests (`dashboard-nav`, `surface-token-isolation`, `preview-photo-isolation`, `storefront-link-prefix`, `single-order-state-writer`, `product-form-contract`). This phase follows that idiom; it does not introduce `@testing-library/react` or `jsdom` for one marketing page. |
| **Config file** | `vitest.config.ts` |
| **Quick run command** | `npm run test:unit` (→ `vitest run tests/unit --reporter=dot`) |
| **Full suite command** | `npm run test:full` (→ `dotenv -e .env.test -- vitest run`, needs the dedicated Neon test branch) |
| **Additional gates** | `npm run lint` (`--max-warnings=0`), `npm run typecheck` (`tsc --noEmit`), `npm run build` |
| **Estimated runtime** | ~5s (unit) |

---

## Sampling Rate

- **After every task commit:** `npm run test:unit`
- **After the wave merge:** `npm run lint && npm run typecheck && npm run test:unit && npm run build`
- **Phase gate:** full suite green, plus a human visual review on a real phone viewport (`checkpoint:human-verify`, Task 3) — this is a design surface and no automated test can assert "looks professional."
- **Max feedback latency:** ~5s per task (unit)
