## Shared Patterns

### Semantic-token-only styling (all new/modified files)
**Source:** `src/app/page.tsx` (current), `src/app/login/page.tsx`, enforced by `tests/unit/surface-token-isolation.test.ts` (bans #1, #2, #4, #6 — literal color, Tailwind palette utility, `brand-accent`, `data-surface="storefront"`)

```tsx
className="border-t border-border bg-muted/40 ..." // never bg-slate-50, never #hex, never oklch(...)
```

### Gold-accent avoidance (D-06, this page's highest-likelihood build failure)
**Source:** `tests/unit/dashboard-nav.test.ts` (exactly-two, sidebar-scoped `variant="gold"` budget)
**Apply to:** every new file in this phase — zero `variant="gold"`, zero decorative gold utility, full stop.

### Copy-in-strings-module, never inline JSX prose
**Source:** `src/lib/strings/flagship.ts` + `src/lib/strings/index.ts` spread idiom; CLAUDE.md binding rule
**Apply to:** `page.tsx` (consumes `strings.root.*` exclusively) and `marketing.ts` (the sole location of every visible string).

### Button-as-link via `render` prop (Base UI idiom)
**Source:** `src/app/page.tsx:36-41` (current, unchanged carry-forward)
```tsx
<Button render={<Link href="/signup" />} className="mt-8 min-h-11 px-6 text-sm font-semibold">
  {strings.root.cta}
</Button>
```
**Apply to:** both the hero CTA and the final-CTA band — identical markup, per Finding 4 ("one dominant CTA, repeated verbatim").

### `next/image` without deprecated `priority`
**Source:** RESEARCH.md Pattern 4; contrast against the *wrong* pattern still live at `src/app/login/page.tsx:30`, `src/app/signup/page.tsx:38`, and three storefront call sites.
**Apply to:** the hero image and the top-lockup logo image — `loading="eager"` + `fetchPriority="high"` (hero only; the logo needs only `loading="eager"`), never `priority`.

### Title-template bypass
**Source:** RESEARCH.md Pattern 5 / Pitfall 8, `src/app/layout.tsx`'s `"%s · EINORT"` template
**Apply to:** `page.tsx`'s `metadata` export only — `title: { absolute: ... }`, not a bare string (the bare-string pattern in `src/app/login/page.tsx:22` is correct *there* because login wants the template applied).
