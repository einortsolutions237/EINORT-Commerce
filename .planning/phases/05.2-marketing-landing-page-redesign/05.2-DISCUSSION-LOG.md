## Post-research follow-up (2026-09-07)

Research (`05.2-RESEARCH.md`) found D-02's original two fallback mechanisms for the hero visual were both structurally dead (a Phase 05.1 containment test blocks any `src/` reference to the placeholder-photo module; there is no `public/` directory to serve a static temporary image from). Two new gray areas surfaced and were put back to the user before UI-SPEC:

| Option | Description | Selected |
|--------|-------------|----------|
| Copy-led hero, image auto-upgrades later | Pure copy/layout hero now, image slot fed directly from the `TEMPLATE_PREVIEWS` manifest — renders nothing extra today, auto-upgrades the moment 05.1-09 populates the manifest | ✓ |
| Block the hero task until Phase 05.1 fully ships | Sequence strictly after 05.1's Wave 5, so a real screenshot exists before the hero is built at all | |

**User's choice:** Copy-led hero, image auto-upgrades later (Recommended) — recorded as **D-05** in CONTEXT.md.

| Option | Description | Selected |
|--------|-------------|----------|
| No gold on this page | Blue/slate only; avoids any risk to `dashboard-nav.test.ts`'s `variant="gold"` exactly-twice assertion | ✓ |
| Allow gold via the raw CSS token, never the variant prop | More visual richness, but requires care about which mechanism is used | |

**User's choice:** No gold on this page (Recommended) — recorded as **D-06** in CONTEXT.md.

A separate research finding — pre-existing fabricated feature claims in `strings.plan.*` (custom domains, discount codes, bulk import, staff accounts, delivery zones, low-stock alerts, none implemented) — was out of this phase's scope (the root page only) and was spawned as its own background task rather than folded into 05.2's plan.
