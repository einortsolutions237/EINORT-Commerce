## Accomplishments

- Six generic, commercial-use-safe, segment-matched placeholder photographs (fashion-apparel, electronics, beauty-cosmetics, grocery-food, furniture-home, general-retail), all CC0 1.0 Universal from StockSnap.io, normalised to a 2000px long edge / JPEG quality 82 / under 400KB each, with EXIF stripped by the re-encode

- `tests/unit/preview-photo-isolation.test.ts`: a 10-assertion source-scanning containment test — no `src/` file references the `preview-assets` directory or the `PREVIEW_PLACEHOLDER_PHOTOS`/`preview-placeholder-photos` tokens, with a named assertion against `src/server/theming/defaults.ts`, anti-vacuity checks in both directions, and positive/negative fixture controls

## Decisions Made

- Single-catalog sourcing (StockSnap.io, CC0) for all six photos rather than mixing Unsplash/Pexels/CC0 — simplifies the licence ledger to one licence family and one verification pattern for the human checkpoint
- `PREVIEW_PLACEHOLDER_PHOTOS` is typed `Readonly<Record<string, string>>` (matching the plan's module contract) rather than `Record<IndustrySegment, string>` — this lets `scripts/preview-placeholder-photos.ts` avoid importing the `server-only`-marked `src/server/theming/registry.ts`, keeping the module importable from a plain `tsx` invocation (05.1-07's generator) that does not resolve the `react-server` condition `server-only` requires. The test file, which runs inside Vitest's `unit` project (where `server-only` is aliased to a stub), does import the real `INDUSTRY_SEGMENTS` to cross-check that all six real segment ids resolve to files on disk.
- Both forbidden D-06 tokens (`preview-assets` directory name, `PREVIEW_PLACEHOLDER_PHOTOS`/`preview-placeholder-photos` module identifier) are checked by one unified `isPreviewAssetOffender` predicate, scoped by `file.startsWith("src/")`, so the real scan and the fixture controls (Tests 6-8 in the plan) provably execute the same code path — the `isBrandAccentOffender` idiom from `surface-token-isolation.test.ts`.
