# Phase 05.1 Plan 05: Template Tile Contract Extension, Show-All Deletion, Segment Ordering, Container Widening Summary

**Extended the shared TemplateTile type with previewUrl/segmentLabel across both RSC flattens, deleted the Show all {N} templates toggle end-to-end, segment-ordered both picker surfaces, and widened the onboarding branding page + its skeleton to max-w-5xl.**

## Performance

## Accomplishments
- `TemplateTile` now carries `previewUrl: string | null` and `segmentLabel: string`, both resolved server-side (RSC) and handed to the `"use client"` picker as finished, plain data — no client-side URL construction, no `onError` fallback.
- The `Show all {N} templates` / `Show recommended only` toggle is gone everywhere: the `showAllToggle` prop, `showAll` state, `visibleTiles` derivation, `sortedBySegment` client helper, the toggle `<button>`, and both strings (`templateShowAll`, `templateShowRecommended`) were deleted. `templateGroupRecommended` / `templateGroupHeading` were added in their place for 05.1-06 to consume.
- Both RSC flattens (`onboarding/branding/page.tsx`, `storefront-editor/page.tsx`) now sort their tile arrays into `INDUSTRY_SEGMENTS` order with an explicit original-index tiebreaker — a pure reorder, `tiles.length` unchanged in both cases.
- The onboarding branding page and its `loading.tsx` skeleton both moved from `max-w-2xl` to `max-w-5xl` in one commit, so the skeleton-to-content transition never jumps.

## Decisions Made
