**This document supersedes, for the picker only:**
- `05-UI-SPEC.md` § Onboarding Template Picker → *Grid and card* (the `grid-cols-2 sm:grid-cols-3` viewport grid and the `p-2` card)
- `05-UI-SPEC.md` § Editor "Change Template" Action → *The picker panel* (grid engine only)
- `05-UI-SPEC.md` § Template Thumbnail Component → *Frame* row only (`aspect-[3/4]`, `min-w-[140px]`)

**Everything else in `04-UI-SPEC.md` and `05-UI-SPEC.md` still governs unchanged** — spacing scale, typography roles, colour tokens, the accent reserved-for lists, the tier-lock/current-card/inert-card semantics, the destructive switch-confirm dialog, D-05's SORT-NEVER-FILTER rule, D-12's surface-token boundary. Where this document is silent, they win.

**The three rules this phase must not break, restated as checkable facts:**
1. **No viewport breakpoint may appear on the picker grid.** `sm:`/`md:`/`lg:` on the grid container is the exact bug this phase exists to fix (the editor rail is `lg:w-80`, a fixed 320px column whose width is decoupled from the window's — `05-RESEARCH.md` Pattern 4).

3. **No literal colour, no Tailwind palette utility, no `data-surface="storefront"`, no `--brand-accent*` utility** anywhere in the redesigned card. `tests/unit/surface-token-isolation.test.ts` bans #1/#2/#3/#4 scan `src/components/**` and `src/app/**` and fail the build. ## Spacing Scale

Inherited verbatim from `04-UI-SPEC.md` — the seven-step closed scale. **Zero new tokens.**

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Lock-icon gap inside the tier chip |
| sm | 8px | Badge inset from the image corner; gap between template name and segment tag |
| md | 16px | Card text-block padding; segment-heading → grid gap |
| lg | 24px | Grid gap between cards (both axes) |
| xl | 32px | Vertical gap between segment groups |
| 2xl | 48px | *(unused this phase)* |
| 3xl | 64px | *(unused this phase)* |

**Exceptions (dimensions/layout constants, not scale tokens — same category as `05-UI-SPEC.md`'s own exceptions table):**

| Exception | Value | Why |
|---|---|---|
| Preview image aspect | `aspect-[16/10]` | Matches D-01's "hero + roughly the next section" crop and the 800×500 WebP the pipeline emits. A card whose frame disagrees with its asset either letterboxes or crops the very thing D-01 chose to include. |
| Minimum rendered card width | **240px** | Below this a real storefront screenshot stops being comparable to another one — the whole point of TMPL-06. This number is what the container breakpoints below are derived from, not a decoration. |
| Container breakpoints | `@lg` = 32rem/512px → 2 cols · `@4xl` = 56rem/896px → 3 cols | Tailwind v4's own named container widths, not new values. See § Grid Engine for the derivation. |
| Onboarding page container | `max-w-5xl` (1024px), up from `max-w-2xl` (672px) | A Tailwind named width. At `max-w-2xl` a 3-up grid yields 205px cards — smaller than today's wireframe tiles, which would not close the gap TMPL-06 names. See § Onboarding Container Widening. |
| Editor rail content width | ~288px (`lg:w-80` − `px-4`) | Existing constant (`editor-shell.tsx:682`), unchanged. Stated because it is the input that makes the grid 1-up there. |
| Segment-heading rule | `pb-2` (8px) above a `border-b border-border` hairline | 8px is the `sm` token; listed here only so the hairline's offset is a stated number rather than an executor's guess. |

Any value outside this table plus `04-`/`05-UI-SPEC.md`'s own exception tables is a contract violation. In particular: **`gap-5` (20px) is not in this scale** — `05-RESEARCH.md`'s example grid uses it; use `gap-6` (24px, the `lg` token) instead. This is a deliberate correction of the research snippet, not an oversight.

## Typography

Inherited from `05-UI-SPEC.md` § Typography, Surfaces 2 & 3. **Zero new sizes, zero new weights, zero new roles.**

| Role | Size | Weight | Line Height | Face |
|------|------|--------|-------------|------|
| Body | 16px | 400 | 1.5 | `font-sans` |
| Label | 14px | 600 | 1.4 | `font-sans` |
| Heading | 24px | 600 | 1.2 | `font-heading` |
| Display | 36px | 600 | 1.1 | `font-heading` |

Declared sizes: **4** (14, 16, 24, 36). Declared weights: **2** (400, 600).

### Card copy mapping — the one documented size/weight pairing outside a role row

| Element | Treatment | Class |
|---|---|---|
| Template display name | **Label** — 14px / 600 / 1.4, `text-foreground` | `text-sm leading-normal font-semibold text-foreground` |
| Segment tag | **Label size at Body weight** — 14px / **400** / 1.4, `text-muted-foreground` | `text-sm leading-normal text-muted-foreground` |
| Segment group heading | **Label** — 14px / 600 / 1.4, `text-foreground` | `text-sm leading-normal font-semibold text-foreground` |
| Retained-above-tier caption | Label size at Body weight, `text-muted-foreground` | `text-sm leading-normal text-muted-foreground` |
| Required-field error | Label size at Body weight, `text-destructive` | `text-sm leading-normal text-destructive` |

**The 14/400 pairing is declared here explicitly rather than left to accident.** It introduces no new size and no new weight — both members are already in the closed sets above. It exists because a 16px muted subtitle beneath a 14px semibold name inverts the visual hierarchy (the subordinate line reads as the dominant one), and because the shipped component already renders `text-sm` on both lines: this ratifies existing, correct behaviour instead of "fixing" it into a worse one.

**Template names stay at Label, never Heading** — unchanged rationale from `05-UI-SPEC.md`: a 50-card grid of Heading-weight names would compete with the page's own `h1` and the panel's own `h2`.

**Segment group headings are not `<h3>` elements.** They are `<span>`/`<div>` text inside the RadioGroup's own labelling structure — promoting them to real headings would inject 6 new nodes into the onboarding page's heading outline beneath an `h1` that already has an `h2`-less structure. Accessibility is served instead by `role="group"` + `aria-labelledby` on each group wrapper (§ Accessibility).

## Color

Inherited from `05-UI-SPEC.md` § Color, surfaces 2/3. **Zero new colour tokens, zero new accent uses.**

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--background` | `oklch(0.984 0.003 247.9)` slate-50 | The onboarding page field / the editor rail field behind the grid |
| Secondary (30%) | `--card` + `--muted` | `oklch(1 0 0)` white / `oklch(0.968 0.007 247.9)` slate-100 | The tile card body (`bg-card`), the image frame's placeholder field (`bg-muted`), the enclosing onboarding Card (`bg-muted`, unchanged) |
| Accent (10%) | `--primary` | `oklch(0.546 0.215 262.9)` brand-600 | See reserved-for list below |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | The required-template-not-chosen error text only |
| Derived | `--ring` | `oklch(0.623 0.188 259.8)` brand-500 | The focus ring (non-discretionary) |

**Accent (`--primary`) reserved for exactly these five things on this surface — no additions:**
1. The **selected** card's border + ring (`border-primary ring-2 ring-primary`)
2. The **`Current`** badge fill (`bg-primary text-primary-foreground`) on the editor's current-template card
3. The editor's **`Want more templates? See plans`** upsell link (`text-primary underline`)
4. The card's **hover border tint** (`hover:border-primary/40`) — an opacity modifier on the already-reserved token, not a sixth use
5. (Derived, non-discretionary) the focus ring, via `--ring`

**Accent is NOT for:** the tier-lock chip (neutral: `bg-background border-border text-foreground` + lock icon — the exact out-of-stock-tile language `04-UI-SPEC.md` locked), the segment group headings, the segment tag, any card shadow, any hover background (that is `--accent`, the neutral slate-100 hover slot).

**Gold (`--gold-accent`) budget is still fully spent** on the pending-claims badge and the "Payment claimed" chip. **No element in this picker uses gold.** The reference is explicit: cards and buttons hover to a faint neutral, never to gold.

**The merchant's `--brand-accent*` family must not be written anywhere in this component.** It resolves to nothing outside `[data-surface="storefront"]` and writing it here is the D-12 boundary violation `tests/unit/surface-token-isolation.test.ts` ban #2 catches.

### The preview image contains storefront colour — this is content, not a token leak

Each preview `.webp` is a photograph of a real storefront and therefore contains that template's own zinc palette and merchant accent as **pixels**. That is the entire point of TMPL-06 and it is categorically different from a token leak: no CSS custom property crosses the surface boundary, no class is written, and the source scanners see an `<Image src>` and nothing else. State this in the component's header comment so a future reader does not "fix" it.

### Dark mode

The dashboard ships a 3-way Light/System/Dark toggle (quick task `260906-egn`). The storefront has **no dark variant by design**, so every generated preview is a light-mode capture (`colorScheme: "light"` is pinned in the screenshot script).

| Rule | Contract |
|---|---|
| Preview images are **never** dimmed, inverted, or filtered in dark mode | `dark:opacity-*`, `dark:invert`, `dark:brightness-*` on the image are forbidden. A dimmed preview misrepresents the template the merchant is about to choose. |
| The bright rectangle is framed, not floated | The image frame carries `border-b border-border`, and the card carries `border`. Both tokens invert correctly under `.dark`, so the screenshot reads as a framed artifact rather than a light leak. |
| Everything else | Uses semantic tokens only, so dark mode is correct by construction. Nothing in this component needs a `dark:` variant. |

## Grid Engine (D-04) — container queries, and the bug this fixes

**The current picker is measurably wrong in the editor.** `template-picker.tsx:136` sets `grid grid-cols-2 gap-4 sm:grid-cols-3`. Those are *viewport* breakpoints. The editor rail is a fixed 320px column with `px-4`, leaving ~288px of content — so any desktop merchant opening "Change template" gets **three columns inside 288px**, roughly 85px per card. D-04's "down to 1-2 if needed" is unreachable with viewport breakpoints at all.

Tailwind CSS v4 ships container queries in core, no plugin.

```tsx
<div className="@container">
  {/* one RadioGroup wraps every group; each group has its own grid */}
  <div className="grid grid-cols-1 gap-6 @lg:grid-cols-2 @4xl:grid-cols-3">
```

### Derivation — why `@lg` and `@4xl`, not `@sm` and `@2xl`

The floor is the **240px minimum card width** exception. `@sm` (384px) → 2 cols yields 180px cards; `@2xl` (672px) → 3 cols yields 208px cards. Both are below the floor and would ship a "redesign" whose cards are smaller than the wireframe tiles they replace.

| Surface / width | Container width | Fires | Columns | Card width | Image |
|---|---|---|---|---|---|
| Editor "Change template" rail | ~288px | none | **1** | ~288px | 288×180 |
| Onboarding, mobile (390px viewport) | ~326px | none | **1** | ~326px | 326×204 |
| Onboarding, tablet (820px viewport) | ~740px | `@lg` | **2** | ~358px | 358×224 |
| Onboarding, desktop at `max-w-5xl` | ~976px | `@lg`, `@4xl` | **3** | ~309px | 309×193 |
| Worst case (container exactly 512px) | 512px | `@lg` | **2** | **244px** | 244×153 |

Minimum card width across every surface and viewport: **244px** ✓ (floor 240px). Target band from the Shopify reference (300–340px) is hit on the two surfaces that matter most: onboarding desktop (309px) and the editor rail (288px).

**Contract test (Wave 0, `tests/unit/template-picker-contract.test.ts`):** the file must contain `@container` and `@lg:grid-cols-` / `@4xl:grid-cols-`, and must contain **no** `sm:grid-cols-`, `md:grid-cols-`, or `lg:grid-cols-`.

## Segment Grouping (resolves `05.1-RESEARCH.md` Open Question 4)

The phase brief names "category grouping" as part of the redesign. It is compatible with D-05's SORT-NEVER-FILTER rule **because grouping is a partition, not a filter**: every tile handed to the component renders in exactly one group, and `Σ group.length === tiles.length` is an invariant a contract test can assert.

| Property | Contract |
|---|---|
| Structure | **One** `<RadioGroup>` wraps N group blocks. Each block = a heading + its own `@container` grid. Never N radio groups (that would fragment arrow-key navigation across the set). |
| Group order — onboarding | The merchant's chosen segment first, then the remaining segments in `INDUSTRY_SEGMENTS` order. Before an industry is picked (Card 2 still empty), plain `INDUSTRY_SEGMENTS` order. |
| Group order — editor | Plain `INDUSTRY_SEGMENTS` order. The editor picker passes no `sortBySegment`; a merchant here is changing template, not declaring an industry. |
| Heading — merchant's own segment (onboarding only) | `Recommended for you · {segment} ({n})` |
| Heading — every other group | `{segment} ({n})` |
| Heading style | Label 14/600 `text-foreground`, `pb-2 border-b border-border`, full grid width |
| Heading → grid gap | 16px (`md`) |
| Group → group gap | 32px (`xl`) |
| Empty group | **Never rendered.** Every one of the six segments has ≥1 template at every tier, but a zero-length group must still be skipped rather than rendering a heading over nothing. |
| Data | `TemplateTile` gains `segmentLabel: string`, flattened by both RSCs from `strings.branding.segments[definition.segment]`. The picker must not index that record itself — `tile.segment` is typed `string`, and narrowing it inside a `"use client"` file would pull registry types across the `server-only` boundary. |

### The `Show all {N} templates` toggle is removed (supersedes `05-UI-SPEC.md`)

`05-UI-SPEC.md` introduced the toggle to make it *visible* that the industry sort hides nothing. Explicit segment headings — every segment named, every count printed, every card on screen — do that job strictly better, and the toggle's own copy ("Show all 50 templates") actively implies a filter that has never existed. Keeping both would leave a control whose two states now render the identical set in a barely different order.

**Removed:** the `showAllToggle` prop, the `showAll` state, the `sortedBySegment()` helper (superseded by grouping), and the strings `branding.templateShowAll` / `branding.templateShowRecommended`.

**D-05 is strengthened, not weakened:** the set rendered is unchanged (every tier-accessible tile plus every locked tile), and the merchant can now *see* that it is complete instead of being told so by a link. ⚠️ This deletes a shipped, previously-spec'd affordance — flagged to the orchestrator for user confirmation before planning.

## Card Anatomy

The transferable elements from the Shopify references are **card size, real preview imagery, and grid polish** — not the "by Shopify" attribution line or the per-card "Add" button, which are Shopify-platform chrome (merchants there install third-party themes; EINORT merchants select a platform template).

```
┌─────────────────────────────────────┐  ← rounded-lg border bg-card overflow-hidden
│ ███████████████████████████████████ │  ← aspect-[16/10] bg-muted, border-b border-border
│ ██  real 800×500 preview  ████████ │     next/image fill object-cover object-top
│ ███████████████████████████████████ │     (or <TemplateThumbnail> fallback, D-05)
├─────────────────────────────────────┤
│ Coastal Linen                       │  ← Label 14/600 text-foreground
│ Fashion & apparel                   │  ← 14/400 text-muted-foreground
└─────────────────────────────────────┘     text block: p-4, gap-2
```

| Property | Contract |
|---|---|
| Card frame | `relative flex flex-col overflow-hidden rounded-lg border bg-card transition-colors duration-200` |
| Card — unselected | `border-border hover:border-primary/40 hover:bg-accent` |
| Card — selected | `border-primary ring-2 ring-primary` (identical selected-state language to the industry tile, unchanged from `05-UI-SPEC.md`) |
| Card — locked | `opacity-60`, no hover transform, no hover border tint, `cursor-not-allowed` on the input |
| Card — current (editor) | Selected treatment + the `Current` badge. **Inert:** no hover transform, no hover border tint; re-selection never fires `onChange` (T-05-35, unchanged) |
| Card padding | **None on the card.** The image is full-bleed to the card's edges (the Shopify Theme Store silhouette); only the text block carries padding. This supersedes the shipped `p-2` wrapper. |
| Image frame | `relative aspect-[16/10] w-full overflow-hidden border-b border-border bg-muted` |
| Image | `next/image` · `fill` · `sizes="(min-width: 1024px) 340px, (min-width: 640px) 50vw, 92vw"` · `className="object-cover object-top transition-transform duration-200 group-hover:scale-[1.02] motion-reduce:transform-none motion-reduce:transition-none"` · `alt=""` (decorative — the `<Label>` is the accessible name via `aria-labelledby`) |
| **Never** `priority` | 50 tiles with `priority` cancels lazy loading and drops ~2 MB on a Douala mobile connection at first paint. `next/image` lazy-loads by default; leave it. Asserted by the contract test. |
| Loading state | The `bg-muted` image frame **is** the placeholder. No `<Skeleton>`, no blur-up, no shimmer — the frame already reserves exact layout space via `aspect-[16/10]`, so there is no shift to mask. |
| Text block | `flex flex-col gap-2 p-4` — name (Label) then segment tag (14/400 muted) |
| Retained-above-tier caption | Appended inside the text block, `text-sm leading-normal text-muted-foreground` (unchanged copy) |
| Focus ring | Unchanged: `has-[:focus-visible]:outline-2 has-[:focus-visible]:outline-offset-2 has-[:focus-visible]:outline-ring` on the card |
| Hover group | The card carries `group` so the image's `group-hover:scale-[1.02]` resolves. Locked and current cards omit `group` (or the scale class) so the lift never suggests an unavailable action. |

### Badges

| Badge | Placement | Treatment |
|---|---|---|
| Tier lock | Centred over the image frame, `pointer-events-none absolute inset-0 flex items-center justify-center p-4` | `Badge variant="outline"` · `border-border bg-background text-foreground` · lock icon `size-3`, gap 4px (`xs`) · copy `Requires {tier}` — unchanged |
| Current (editor) | `absolute top-2 left-2` (8px inset, `sm`; up from the shipped 4px, proportional to the larger card) | `bg-primary text-primary-foreground` · copy `Current` — unchanged |

### No device bezel

The Shopify **Theme Store** wraps its screenshots in a phone frame; the user's own **admin "Discover themes"** screenshot — the primary target named in CONTEXT.md — uses plain rectangular screenshots with a subtle border. This spec follows the admin reference: **no bezel**. Reasons, recorded so it is not re-litigated: D-01's crop is a 1280px-wide *desktop* render and a phone bezel would misrepresent it; and a bezel spends 20–30% of an already-288px card on decorative chrome.

### No per-card secondary button

No hover "Preview" or "Add" button. Selection *is* the action (the whole card is one radio target). A per-card preview button would require a lightbox or a new route, both out of this phase's boundary.

## D-05 Fallback: the wireframe inside the new frame

When `previewUrl === null`, the card renders `<TemplateThumbnail>` **inside the same `aspect-[16/10]` frame**, not beside it and not in place of it. The decision is made from manifest state in the RSC, before render — never via `onError`, which flashes a broken image, logs console noise, and cannot catch the un-allowlisted-host case at all (`next/image` throws there rather than failing to load).

**The frame conflict, and its resolution.** `template-thumbnail.tsx:298` hardcodes `aspect-[3/4] rounded-md border border-border bg-background overflow-hidden min-w-[140px]` — a *portrait* frame with a minimum width. Dropped into a 16/10 landscape card slot it overflows.

| Contract | Value |
|---|---|
| Change to `TemplateThumbnail` | **One optional prop**: `className?: string`, merged onto the existing frame `<div>` via `cn()`. The default value is today's exact class string, so every current call site is byte-identical in behaviour. No other change to that file. |
| What the picker passes | `className="h-full w-full aspect-auto min-w-0 rounded-none border-0"` — neutralizes the portrait aspect, the min-width, and the double border/radius (the card's own image frame already supplies both). |
| Result | The section stack compresses vertically inside the landscape frame. Its blocks are `flex`-weighted, so it degrades to a legible landscape wireframe. It is a rare safety net, not a steady state (D-05), so proportional perfection is not required — *not broken* is. |
| Colour | Unchanged. Exactly one `AccentBlock` per render, still the only `style` attribute in that file. |
| A11y | Unchanged: `aria-hidden="true"` on the frame; the card's `<Label>` is the accessible name. |
| Copy | **None.** No "Preview unavailable" text, no error icon, no skeleton — D-05 explicitly rejects all three. The fallback is silent by design. |
| Header comment | `template-thumbnail.tsx`'s header currently argues *against* stored images ("50 templates in R2 … would create a regeneration obligation"). TMPL-06 overrides that decision. The plan must **update that header** to record the override and the component's new fallback role, rather than leave a comment contradicting shipped behaviour. |

## Onboarding Container Widening

`src/app/onboarding/branding/page.tsx:185` — `max-w-2xl` → `max-w-5xl`.

| | Content width in the picker's Card | Columns | Card width |
|---|---|---|---|
| `max-w-2xl` (672px) — today | ~624px | 2 | ~300px … but only 2-up for 50 cards |
| `max-w-4xl` (896px) | ~848px | 2 | ~412px — too wide, and 25 rows for 50 cards |
| **`max-w-5xl` (1024px)** | ~976px | **3** | **~309px** ✓ inside the 300–340px reference band |

**Confirms `05.1-RESEARCH.md` assumption A7** (whether widening breaks the industry-segment tile grid above): it does not break, and no other change is needed.

- The industry tile grid stays `grid-cols-2 sm:grid-cols-3`. Its 6 tiles simply render larger (~200px → ~325px). **Do not add a fourth column step** — 6 tiles across 4 columns leaves a 2-tile orphan row, which is worse than airy tiles.
- The logo and brand-colour cards become wide form rows. That is the normal dashboard idiom and matches the reference's own full-width settings cards.
- `src/app/onboarding/branding/loading.tsx:17` also hardcodes `max-w-2xl`. **It must be widened in the same task** or the skeleton→content transition will visibly jump.
- The page's own `px-4 sm:px-8` outer padding is unchanged.

⚠️ This widens the *whole* branding page, not just the picker card. Confirm visually once during execution.

## Interaction & States

| State | Contract |
|---|---|
| Default (onboarding) | No pre-selected template. D-07 requires a real, deliberate pick — unchanged. |
| Hover (selectable card) | Border tints to `primary/40`, background to `accent` (neutral slate-100), image scales to 1.02, all at `duration-200`. Guarded by `motion-reduce:`. |
| Focus | Keyboard focus on the hidden radio surfaces the card's `has-[:focus-visible]` outline in `--ring`. Arrow keys move within the single RadioGroup, across group boundaries. |
| Selected | `border-primary ring-2 ring-primary`. |
| Locked | `opacity-60`, neutral `Requires {tier}` chip centred on the image, radio `disabled` + `aria-disabled="true"`, tooltip on hover/focus reading `Available on the {tier} plan.` No hover lift, no dialog on click. |
| Current (editor) | `Current` badge, selected ring, inert — clicking never fires `onChange` and never opens the switch dialog. |
| Selecting a different template (editor) | Opens the existing destructive `alert-dialog` unchanged (`05-UI-SPEC.md` § Selecting a *different* template). This phase changes nothing about that dialog. |
| Required-field error (onboarding) | Inline beneath the last group, `text-destructive`, copy `Choose a template to continue.` — unchanged. |

## Decisions Made Under "Claude's Discretion"

`05.1-CONTEXT.md` § Claude's Discretion hands "exact grid card visual details (typography scale, spacing, hover treatment) beyond the aspect-ratio/column-count decisions" to this pass, and `05.1-RESEARCH.md` explicitly defers Open Question 4 and assumption A7 here. Settled below so they are not re-settled at build time.

| # | Item | Decision | Rationale |
|---|---|---|---|
| U-01 | Container breakpoints | `@lg` (512px) → 2 cols · `@4xl` (896px) → 3 cols, **not** research's `@sm`/`@2xl` | `@sm`/`@2xl` yield 180px/208px cards — smaller than the wireframe tiles they replace. Derived from the 240px minimum-card-width floor. |
| U-02 | Grid gap | `gap-6` (24px, `lg`), **not** research's `gap-5` (20px) | 20px is not in the closed seven-step spacing scale. |
| U-03 | Card padding | None on the card; image full-bleed, `p-4` on the text block only | The Shopify Theme Store silhouette. The shipped `p-2` inset frame makes the screenshot read as a thumbnail rather than a preview. |
| U-04 | Image aspect | `aspect-[16/10]` | Matches D-01's crop and the 800×500 asset exactly — no letterbox, no re-crop. |
| U-05 | Device bezel | **No bezel** | The user's admin "Discover themes" reference uses plain framed screenshots; D-01's crop is a desktop render a phone frame would misrepresent; a bezel costs 20–30% of a 288px rail card. |
| U-06 | Per-card secondary button | **None** — the whole card is the radio target | Shopify's "Add" is install-a-third-party-theme chrome with no EINORT analogue; a "Preview" button needs a lightbox or route, both out of boundary. |
| U-07 | Segment grouping (**OQ4**) | Group headings in both surfaces, all groups always rendered, merchant's segment hoisted first in onboarding | Grouping is a partition, not a filter — D-05 intact. It is also what makes a 1-column, 50-card editor rail navigable at all. **Confirmed by user 2026-09-07.** |
| U-08 | `Show all {N}` toggle | **Removed**, with its two strings | Explicit segment headings + counts prove "nothing is hidden" better than a link whose copy implies a filter that never existed. **Confirmed by user 2026-09-07** (this deletes a shipped affordance; sign-off obtained before planning). |
| U-09 | Onboarding container (**A7**) | `max-w-2xl` → `max-w-5xl`, page-wide; industry grid keeps `grid-cols-2 sm:grid-cols-3`; `loading.tsx` widened in the same task | `max-w-5xl` is the only named width that lands 3-up cards in the 300–340px reference band. A fourth industry column would orphan a 2-tile row. **Confirmed by user 2026-09-07.** |
| U-10 | Segment-tag typography | Label size at Body weight (14/400) | Adds no size and no weight; prevents a 16px muted subtitle from out-weighing a 14px semibold name; ratifies the shipped `text-sm`. |
| U-11 | Fallback frame conflict | One optional `className` prop on `TemplateThumbnail`, defaulting to today's exact classes; the picker neutralizes aspect/min-width/border/radius | The smallest change that makes a portrait wireframe survive in a landscape frame without forking the component or touching any existing call site. |
| U-12 | Group heading elements | `<span>` + `role="group"`/`aria-labelledby`, not `<h3>` | Six new heading nodes would distort the onboarding page's heading outline; group semantics carry the same information to assistive tech. |
| U-13 | Dark mode treatment of previews | Never dimmed/inverted/filtered; framed with `border-border` instead | A dimmed preview misrepresents the template being chosen. The storefront ships no dark variant, so light captures are correct by construction. |
| U-14 | Loading state | The `bg-muted` `aspect-[16/10]` frame is the placeholder — no `<Skeleton>` | The frame already reserves exact layout space; there is no shift to mask, and D-05 rejects a generic skeleton for the missing-image case. |
