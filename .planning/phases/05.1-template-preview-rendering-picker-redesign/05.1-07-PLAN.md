## Phase Goal

> **ROADMAP `**Goal:**` verbatim (NOT in `As a ... I want to ... so that ...` user-story form — flagged to the orchestrator; run `/gsd mvp-phase 05.1` to convert):**
>
> The template picker (onboarding and the storefront editor's "Change template" action) shows a real rendered screenshot per template in a large, polished grid — not the placeholder CSS-wireframe thumbnails Phase 5 shipped — closing the gap against the owner-supplied Shopify Discover-Themes reference before Phase 5's Wave 6 builds its 50-template contact sheet on top of it.

**MVP-mode note:** this plan builds the generator but deliberately does not run it across all 50 templates — plan 05.1-08 does that behind a calibration checkpoint, because `05.1-RESEARCH.md` Pitfall 6 flags the crop rectangle as measure-don't-assume and A3 marks the arithmetic unverified. Building and calibrating in one plan would mean fifty possibly-wrong images before anyone looked at one.

<objective>
Write `scripts/generate-template-previews.ts`: a rerunnable, fail-closed CLI that reseeds one guarded scratch tenant to each template's `TEMPLATE_DEFAULTS` in turn, screenshots the real published storefront home page with Playwright, pipes the PNG through the existing Sharp preset and R2 upload path, and emits the generated manifest.

Purpose: D-02 locks one-time build-script generation and requires the re-run path be "an explicit, documented command, not an ad-hoc script only the original author knows how to invoke". `05.1-RESEARCH.md` Pattern 1 establishes why this reseeds rather than adding a route: `src/proxy.ts:65` hard-404s every `/s/*` path on every host, `surface-token-isolation.test.ts` ban #4 forbids `data-surface="storefront"` outside `src/app/s/`, and `s/[slug]/layout.tsx` injects that tenant's own accent — so the only way to get pixel-accurate output is to screenshot the real thing.
Output: one script, one npm script entry, one README section.
</objective>
