### `scripts/generate-template-previews.ts` (script/CLI, batch + file-I/O)

**Primary analog:** `scripts/generate-brand-icons.mjs` — the only other rerunnable asset generator in the repo.
**Secondary analog:** `tests/setup/seed-two-tenants.ts` — for the destructive-write guard and the build-your-own-Prisma-client posture.

**Header + rerunnable framing** — copy this exact framing (`scripts/generate-brand-icons.mjs:1-9`):
```js
// Rerunnable generator for the platform's favicon/icon/apple-icon files.
//
// The master brand asset (src/assets/brand/einort-logo.png) is the single
// source of truth for every derived icon. This script is not a one-off: it
// exists so a future re-export of the master mark (new colors, a redraw)

// wrong master asset fails loudly here instead of shipping a corrupt icon.
```
→ D-02 requires the *same* "this is not a one-off, it is a documented command" framing, naming `npm run templates:previews`.

**Path resolution from the script's own URL** (`scripts/generate-brand-icons.mjs:11-18`) — do **not** use `process.cwd()`:

→ This is also how the manifest's write target and the placeholder-photo directory must be resolved. RESEARCH Pitfall 3 additionally requires **relative** imports (`../src/server/theming/defaults`), never the `@/` alias.

**Fail-loud-before-doing-work + `process.exitCode`** (`scripts/generate-brand-icons.mjs:20-30`, `:93-97`):

**The destructive-target guard** — copy the *whole shape* from `tests/setup/seed-two-tenants.ts:49-52, 139-202`:
```ts
/** Raised when the seed is pointed at anything that is not the test branch. */
export class UnsafeSeedTargetError extends Error {

}
```
```ts
export function assertSafeSeedTarget(connectionString: string): void {
  const target = endpointIdOf(connectionString);

  for (const devEndpoint of developmentEndpoints()) {
    if (devEndpoint === target) {
      throw new UnsafeSeedTargetError(
        `Refusing to seed: the target endpoint "${target}" is the same Neon ` +
          "endpoint as DATABASE_URL/DIRECT_URL in .env.local — that is the " +
          "development branch. This fixture TRUNCATEs every table, so running " +
          "it there would be unrecoverable data loss.\n" +
          "Point TEST_DATABASE_URL at the dedicated `einort-test` branch.",
      );
    }
  }

  const allowed = allowedEndpoints();
  if (!allowed.includes(target)) {
    throw new UnsafeSeedTargetError(
      `Refusing to seed: endpoint "${target}" is not a known test endpoint.\n` +
        `Allowed: ${allowed.join(", ")}\n` + /* … actionable remediation … */
    );
  }
}
```
```ts
export function resolveSeedTargetUrl(explicit?: string): string {
  const candidate = explicit ?? process.env.TEST_DATABASE_URL;
  if (!candidate || candidate.trim() === "") {
    throw new UnsafeSeedTargetError(
      "Refusing to seed: TEST_DATABASE_URL is not set.\n" + /* … names the branch, names the command … */
    );
  }
  const url = candidate.trim();
  assertSafeSeedTarget(url);
  return url;
}
```
**Four properties to copy verbatim, not paraphrase:**
1. Named error class with `override readonly name` (a transpiled subclass otherwise logs `name: "Error"`).
2. **Never falls back** to the ambient variable — `resolveSeedTargetUrl` reads `TEST_DATABASE_URL` and refuses rather than reading `DATABASE_URL`. The preview script's `TEMPLATE_PREVIEW_STORE_SLUG` must behave identically (RESEARCH Open Question 2).
3. Two independent layers (denylist *then* allowlist). The preview script's inverse pair: **must** be the configured scratch slug **and** that store must have zero `Order` rows.
4. Every message names the remediation command, not just the fault.

**Reading env directly is correct here** (`tests/setup/seed-two-tenants.ts:39-45` header):
> "The client here is built explicitly against the resolved test connection string rather than imported from `src/server/db/*`. That is deliberate too: it removes any possibility of a truncate-and-reseed inheriting whatever ambient `DATABASE_URL` happens to be loaded, and it keeps this module importable from a plain `tsx` script (the `src/server/db/*` modules open with `import "server-only"`, which throws outside a `react-server` resolution)."
→ The `src/env.ts`-only rule from CLAUDE.md does **not** bind `scripts/**` or `tests/setup/**`. State this in the script header so nobody "fixes" it.

**Sharp + R2 legs — do NOT hand-roll.** Call the existing functions:
- `processImage(pngBuffer, "templatePreview")` from `src/server/images/pipeline.ts:165`
- `putObject(key, body, contentType)` from `src/server/images/r2.ts:220-234`
- key from `templatePreviewPrefixFor(key) + "/card.webp"` (new, see below)

**No analog for:** the Playwright block. Use `05.1-RESEARCH.md` § Code Examples → "Playwright context + screenshot" verbatim (`reducedMotion: "reduce"`, `animations: "disabled"`, `colorScheme: "light"`, `locale: "fr-CM"`, `timezoneId: "Africa/Douala"`, `deviceScaleFactor: 2`), and Pitfall 6's measure-don't-assume clip.

```ts
/** Every `.tsx` file under a directory, recursively, as repo-relative paths. */
function tsxFilesUnder(dir: string): string[] {
  const absolute = join(repoRoot, dir);
  if (!existsSync(absolute)) return [];

  const found: string[] = [];
  for (const entry of readdirSync(absolute, { withFileTypes: true })) {
    const child = `${dir}/${entry.name}`;
    if (entry.isDirectory()) {
      found.push(...tsxFilesUnder(child));
    } else if (entry.name.endsWith(".tsx")) {
      found.push(child);
    }
  }
  return found;
}
```
