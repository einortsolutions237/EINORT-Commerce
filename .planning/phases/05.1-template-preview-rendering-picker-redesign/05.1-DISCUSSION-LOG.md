## Screenshot framing

| Option | Description | Selected |
|--------|-------------|----------|
| Cropped hero + first section | A fixed-height crop capturing the hero and roughly the next section — matches Shopify's card aspect ratio, loads fast, still shows enough structure/accent to tell templates apart | ✓ |
| Hero only | Just the hero section, cropped tight — fastest/smallest, but less distinct between templates sharing a hero variant | |
| Full scrollable homepage | The entire default homepage compressed into one tall image — shows everything but doesn't match card proportions | |

**User's choice:** Cropped hero + first section (Recommended)
**Notes:** None beyond the selection.

---

## Rendering & regeneration strategy

| Option | Description | Selected |
|--------|-------------|----------|
| One-time build/seed script | A Node script using a new headless-browser dependency (human-approved like next-themes) renders all 50 templates once and uploads to R2. No runtime rendering cost; manual re-run when a template's design changes | ✓ |
| On-demand, render-and-cache on first view | First viewer triggers a real-time render, cached after — avoids manual regeneration but adds render-time latency risk and system complexity | |

**User's choice:** One-time build/seed script (Recommended)
**Notes:** None beyond the selection.

---

## Grid layout per surface

| Option | Description | Selected |
|--------|-------------|----------|
| Same cards, responsive column count | One shared card design — onboarding shows more columns (more width), editor panel shows fewer (down to 1-2) — consistent visual language, no duplicate component | ✓ |
| Two distinct card sizes | A larger card for onboarding, a compact card for the editor's narrower panel — optimized per context, at the cost of two variants to keep in sync | |

**User's choice:** Same cards, responsive column count (Recommended)
**Notes:** None beyond the selection.

---

## Fallback behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Fall back to the existing CSS-wireframe thumbnail | Reuse 05-09's geometric wireframe component as a graceful degrade — never a broken image icon or blank tile. Should rarely be seen given the one-time-script strategy | ✓ |
| A generic loading skeleton | A neutral shimmer/skeleton placeholder instead — makes loading state visually obvious rather than presenting a wireframe as if final | |

**User's choice:** Fall back to the existing CSS-wireframe thumbnail (Recommended)
**Notes:** None beyond the selection.
