## Phase Goal

> **ROADMAP `**Goal:**` verbatim (NOT in `As a … I want to … so that …` user-story form — flagged to the orchestrator; run `/gsd mvp-phase 05.1` to convert):**
>
> The template picker (onboarding and the storefront editor's "Change template" action) shows a real rendered screenshot per template in a large, polished grid — not the placeholder CSS-wireframe thumbnails Phase 5 shipped — closing the gap against the owner-supplied Shopify Discover-Themes reference before Phase 5's Wave 6 builds its 50-template contact sheet on top of it.

**MVP-mode note (interface-first exception, taken deliberately):** the guard is extracted into its own module for exactly one reason — `tests/setup/seed-two-tenants.ts`'s `assertSafeSeedTarget` is unit-testable *because* it was extracted, and `tests/unit/seed-guard.test.ts` exists to prove it. A guard buried inline in the generation script cannot be observed refusing. Interface-first here is a testability requirement, not a layering preference.

<objective>

Purpose: `05.1-RESEARCH.md` § Security Domain names "destructive script run against the production database" as this phase's highest-severity threat. `05.1-PATTERNS.md` maps the exact analog — `tests/setup/seed-two-tenants.ts`'s `UnsafeSeedTargetError` + `assertSafeSeedTarget` + `resolveSeedTargetUrl` triple, with four properties to copy verbatim rather than paraphrase.
Output: one pure guard module under `scripts/`, its refusal test, and the `.env.example` entry that documents the variable it demands.
</objective>

```ts
export class UnsafePreviewTargetError extends Error {
  override readonly name = "UnsafePreviewTargetError";
}

/** Reads TEMPLATE_PREVIEW_STORE_SLUG. Refuses; never falls back. */
export function resolvePreviewStoreSlug(explicit?: string): string;

/** The second layer: the store the script actually resolved must BE the configured one, and must be empty of orders. */
export function assertSafePreviewTarget(target: {
  readonly slug: string;
  readonly configuredSlug: string;
  readonly orderCount: number;
}): void;
```

Slug shape is the project's existing store-slug convention: lowercase alphanumerics and hyphens, no leading/trailing hyphen. `src/server/tenant/slug.ts` owns `storeSlugSchema` — read it and reuse its rule rather than authoring a second spelling of the same regex. This module lives under `scripts/`, outside the `src/**` ESLint zone, so a plain relative import (`../src/server/tenant/slug`) or a locally-declared pattern are both acceptable; prefer reuse.
</interfaces>
