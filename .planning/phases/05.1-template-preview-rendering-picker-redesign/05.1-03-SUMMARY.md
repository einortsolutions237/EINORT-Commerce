## Decisions Made
- **Strict-equality reuse of `storeSlugSchema`:** `storeSlugSchema` normalizes (`trim().toLowerCase()`) before validating, which is correct for the signup form but wrong for a destructive-write target guard — a slug that only validates after being silently re-cased is exactly the "close enough" match the guard exists to catch (plan Test 4 requires `"UPPER"` to throw). Rather than re-authoring `SLUG_PATTERN` as a second regex, `resolvePreviewStoreSlug` calls `storeSlugSchema.safeParse()` and additionally requires `parsed.data === candidate` (byte-for-byte), so any normalization at all is treated as a refusal rather than a silent correction. This satisfies the plan's "prefer reuse" instruction while still passing the case-sensitivity behavior test.
- **`.env.example`-only documentation:** followed the plan's explicit instruction not to add the variable to `src/env.ts` (would make a script-only variable a hard boot-time requirement on every environment including Vercel) or to `.env.test.example` (isolation suite has no use for it).
